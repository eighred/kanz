### Phase 11 — Automated fund-management & multi-exchange execution system (opened 2026-07)

- **EXEC-M6a/b** — the kill-switch, and the handle to pull it. The `Halted` seam was wired to a **constant `false`** and set by no binary, while `pkg/alpha`'s Runner ticked engines every 100ms with no brake at all — `kill -9` was the risk control. Now one shared **`translate.Gate`**, held by both brains and checked at the webhook perimeter *and* at the top of every alpha tick (engines are not even evaluated while halted — a halted system decides nothing, rather than deciding and discarding). **Deny-by-default**: constructed CLOSED, and only `OPERATING_MODE_NORMAL` trades. **Fail-closed**: a NATS disconnect trips it — `pkg/bus` could not even *observe* a disconnect before (`MaxReconnects: -1` heals silently), so `NATSConfig` gained `OnDisconnect`/`OnReconnect`, with `ClosedHandler` covering the terminal case the disconnect handler misses. **Latching**: reconnection does not clear it and neither can a `system:`-issued ModeChanged; only an operator does — matching `lifecycle.v1`'s own contract that HALTED "requires intervention to leave". The gate is a **required** field in `translate.Options`, because the seam it replaced was optional, defaulted open, and was never wired: an optional brake is an absent brake, and the compiler now refuses to build a translator without one. Keys off the existing **`lifecycle.v1.ModeChanged`** (`component="system"`), NOT a new status enum — a second one would be the parallel system the gate exists to prevent. An undecodable halt FACT trips the gate: "I could not read the brake signal" must never resolve to "keep trading". `cmd/kanz-halt` is the operator's standalone break-glass handle, sharing no code with the trading pipeline (the subject constant lives in a zero-dep `internal/platform/mode` that both ends import) — the one tool that must work while the system is on fire cannot be coupled to the system that is on fire. It rejects `--resume --by system:…` at the flag boundary, since the gate would ignore it and the resume would silently no-op. Verified against a live NATS/JetStream spine, both directions.

- **EXEC-M5b** — the native-alpha boundary (`pkg/alpha`), delivered without a line of alpha math in this repo. **The board's original framing was wrong and the code was ground truth:** publishing a `StrategySignal` FACT onto `strategy.signal.received` executes *nothing* — nothing subscribes to it; it is the audit root, and webhook-ingest fans out the `SubmitOrder` COMMANDs itself in the same call. So the native port had to do both. Rather than clone the fan-out (a second execution path the OMS's pre-trade gates could drift away from), the signal→FACT→commands core was extracted to **`internal/signal/translate`**, now shared by webhook-ingest and native alpha — webhook-ingest's entire test suite passes unchanged over it. `pkg/alpha` is the public boundary the **restricted layer imports as a separate module** (dependency runs private→public; `kanz/go.mod` stays free of a private require): `MarketView` (read-seam — best bid/ask, top-N depth, windowed aggressive buy/sell volume, last price; raw state, no indicators), `Engine`, `Intent`, and a `Runner` that owns the edge. Kanz's own market-ingest runs **the same Runner with zero engines** — it folds and snapshots and decides nothing. The edge internals are re-exported as **type aliases** (`DepthSource`/`Trade`/…) because an external module cannot name a `kanz/internal` type — without them the boundary would compile and be useless; **verified from a real external module** whose only direct kanz import is `pkg/alpha`. New `internal/marketedge/trades`: the trade tape (Binance `@trade`, OKX `trades`, sim), time-bounded, attributing volume by **aggressor** — Binance's `m` flag means *buyer-is-maker*, i.e. a taker SELL, and reading it as a buy inverts every volume-delta signal. `Intent.TimeInForce` carries **IOC** to every leg (an arb leg that rests turns a hedge into naked exposure). Also collapsed the **five** duplicate `dec` packages into one `internal/dec` (the Milestone-5 zero-float consolidation the market-ingest doc anticipated). All four tag combos green; default binaries still vendor-free.
- **EXEC-M5c** — live venue depth reaches the books (`services/market-ingest`). `depth.BinanceSource` (`//go:build binance`, `<symbol>@depth@100ms` diff stream + the `/api/v3/depth` REST anchor) and `depth.OKXSource` (`//go:build okx`, public v5 `books` channel) implement `depth.DepthSource` over the real `coder/websocket` transport; the sim stays the vendor-free default. Each source **owns its resequencing** and normalizes the venue's native chain onto the one rule the book checks: Binance follows the documented procedure (stream first, then REST anchor, drop `u <= lastUpdateId`, first applied event must straddle `U <= lastUpdateId+1 <= u`, then exact `U == prev u + 1`); OKX uses its native `seqId`/`prevSeqId`, skips repeated-`seqId` no-change frames, and resubscribes to re-anchor. Any break **re-anchors on a fresh snapshot** — never an out-of-order fold. Depth is public: no API keys. One book+engine per instrument **per venue** (books never merged; both tags ⇒ two books), which is the shape the cross-venue engine reads. The DNS-bypass dialer was promoted to `internal/exchange/netdial` on the second-consumer trigger — untagged and stdlib-only, so the default binaries of *both* market-ingest and oms remain vendor-free (verified via `go list -deps`); its websocket client carries a zero `Timeout` because `coder/websocket` rejects a client with one and it would kill the long-lived stream. Hermetic tests drive the real websocket over `httptest` and pin the anchor/straddle/gap-re-anchor/zero-size-level/subscribe-error paths on both venues; all four tag combos green.
- **EXEC-M4d** — operational parity closed: the healing seam now has a live writer and runs on both venues. Two halves. (1) **The venue-close dispatch path** — the real gap: `handleCancel` marked an order CANCELLED in the ledger and *never told the exchange*, leaving it resting and still fillable at the venue. New optional `execution.Closer` capability on `Venue` (`CancelOrder`, addressed by our deterministic clOrdId) implemented by `BinanceVenue` (DELETE /api/v3/order; -2011 ⇒ already gone ⇒ confirmed) and `OKXVenue` (POST /api/v5/trade/cancel-order; 51400/51401/51402 ⇒ confirmed); the OMS type-asserts it, **Tracks the `CloseIntent` before dispatch** (the hung-call / ambiguous-timeout / process-death window a post-ack Track would miss), and `Resolve`s on a confirmed withdrawal. An unconfirmed cancel stays tracked for the watchdog and does **not** nack the command — the ledger must never freeze on an unresponsive exchange. A cancelled *resting* order carries no `SweepSide`/`Leaves`: it never traded, so sweeping it would fabricate an opposite-direction position (only a failed position-flatten leaves exposure to sweep). (2) **Binance healing parity** — `Reconciler.RunHealing`/`HealClosures`/`forceSweep` mirroring OKX over the same untagged seam (1500ms timeout, 500ms watchdog tick, query by clOrdId → StateHealed on venue truth, else force-clear + idempotent `heal-`+id market sweep + balance re-anchor), plus `binanceREST.cancelOrder`/`sweepMarket`. The `CloseRegistry` moved to the untagged composition root — one process-wide registry, written by the OMS, drained by whichever venue watchdogs are compiled in. New `CloseTracker` (write) half beside `PendingCloses` (read). Hermetic tests mirror the OKX suite + cover the cancel-never-sweeps invariant and the Closer confirm/surface discipline; all four tag combos green, default binary still vendor-free.
- **EXEC-M4c** — In-Flight Certainty (the healing seam) + production IP hardening (`services/oms`). A close command (cancel / IOC market flatten) races the venue; if its ack stays unconfirmed past a hard 1500ms timeout the ledger must never freeze. Untagged `CloseIntent`/`PendingCloses` seam + in-memory `CloseRegistry` (retry preserves the original timeout clock); the OKX reconciler's `RunHealing` watchdog (500ms tick) queries each due close by clOrdId → `StateHealed` with venue truth if terminal, else force-clears (StateHealed → CANCELLED) and sweeps the residual with an aggressive market order (idempotent `heal-`+id clOrdId, never double-flattens) then re-anchors balances from real venue truth (never fabricated). Wired at `venues_okx.go`. Hardening: Makefile `release` target strips symbols/DWARF + trimpath (`-s -w`, verified `nm`→no symbols, 27→19MB) to resist decompilation; `ErrEgressDenied` types a 401/403 auth-boundary denial (a prod key run outside the exchange IP allowlist) as a non-retryable structural fault; secrets stay memory-only. Binance parity of the healing seam is a trivial follow-on (shared seam).
- **EXEC-M5a** — the native-alpha edge foundation (`services/market-ingest`, additive `market.v1.OrderBookSnapshot`/`OrderBookDelta`/`PriceLevel` + `signal.v1.SignalSource`/`StrategySignal.source`). Process-isolated edge that folds exchange L2 depth into a concurrent in-memory `book.Book` off the bus (the hot path — raw full-rate depth never republished) and publishes only bounded periodic `market.book.snapshot` FACTs for replay/audit; strict sequence-chain gap detection re-snapshots rather than folding out of order; exact `big.Rat` prices. `depth.DepthSource` transport seam with a deterministic vendor-free sim (mic "SIM") as default; live venue sources bind behind build tags (EXEC-M5c). Foundation for the OBI/arbitrage engines (EXEC-M5b).
- **EXEC-M4b** — OKX operational parity (`services/oms`, `//go:build okx`): OKX v5 private user-data websocket → `OrderFilled`/`PartiallyFilled` FACTs (fill_id `instId-tradeId`, dedups the sync path), background REST reconciliation → correcting `StateHealed`/`BalanceReconciled` FACTs, ticker feed → tv-sync MarkSource, all bundled in `OKXConnector` and wired at the composition root behind the OKX tag.
