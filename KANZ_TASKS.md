### Buildable now — operational parity (do first)

**Recommended next: DATA-M8b — exact decimals on the pricing/valuation path (`services/datamaster/internal/pricing`).** A price is money. The standing constraint is that money never rides a float, and `pricing.Candidate.Price`, `Arbitration.Chosen`, `Exception.Override.ChosenPrice` and the `exception_overrides.chosen_price` column are all `float64`/double. The package comment defends this as "a derived oversight statistic" — that was true when arbitration compared numbers and nothing kept them. It is no longer true: DATA-M8a made the override **durable and audited**, so a named human's accepted price is now a persisted, signed compliance record, and it is persisted as a rounded binary double.

**Why this is next, and not after a vendor feed:** the consequence is currently latent only because nothing implements `feed.RefSource` — there is no real price in this path to round. The moment a vendor adapter lands, the first genuine price the platform masters gets rounded on its way into an audited store, and by then the schema, the API and the stored history are all committed to the wrong type. Fix the type before the data arrives. This is also why DATA-M8a deliberately left `handlePrice` reading through to the vendors and shipped **no durable price store**: a NUMERIC column filled from a float64 would launder a rounded number into an audited price. Reuse `internal/dec` (`big.Rat`, `ParseRat`/`Str`) — the same conversion the regulatory filing path took in `b390623` (`LineItem.Value` → `*big.Rat`, marshalling as a decimal **string**, never a JSON number). Note the honest exception that path established: a genuinely irrational result (there, a sqrt) may stay float, but a price, a median of prices, and a human's chosen price are all exact. · buildable — standing-constraint violation on a persisted, audited surface; blocks a real vendor feed

### Phase 11 — Automated fund-management & multi-exchange execution system (opened 2026-07)

- **DATA-M8a** — the golden store had no writer. `store.PostgresGolden`, `store.PostgresExceptions`, `master.Resolve` and `pricing.Arbitrate` all shipped with MASTER-01, all tested, and **nothing ever constructed or drove them**: `golden_records` had no writer, the read API called `master.Resolve` over the live vendor feeds *inside every request*, and the pricing-oversight exception queue — the surface a human works — was a `map` behind a mutex. New `internal/projector` is the consumer: it pulls every vendor on a cycle, resolves one golden record per instrument, persists it, and files every break into the durable exception store; the read path now serves what was mastered rather than mastering as a side effect of being read. **Three defects were real regardless of feeds.** (1) **Operator overrides did not survive a restart** — an override is a named human accepting a price the system flagged, and it lived in that map; the append-only `exception_overrides` table (actor, reason, identity `seq`) existed and was wired to nothing, so a rolling update silently deleted a compliance record. Proven fixed by `kill -9` against a live non-superuser Postgres: the override survives, and a re-detected break does **not** re-open behind it (the deterministic exception id + `ON CONFLICT DO NOTHING` preserve the review state a human already gave it). (2) **A price was arbitrated against the whole book** — `pricing.Candidate` carried no instrument id, so a feed's entire price list went to `Arbitrate` for whichever instrument was asked for; with the test fixture the consensus for INST1 came back as **115**, the median of INST1's quotes *and another instrument's 999*. Candidates now carry what they are a price of. (3) **A vendor outage would have quietly rewritten the master** — survivorship resolves each field from the highest-priority vendor that *has* it, so projecting over a subset does not yield a partial record, it yields a **different** one, sourced from a fallback and stamped with provenance as though intended; a refresh is now all-or-nothing and the store keeps the last good projection. **The fabrication guard (4th instance)**: canned `SimFeed` records, once resolved into `golden_records`, are indistinguishable from mastered vendor data and are trusted as an instrument's identity by everything downstream — the service now refuses to start with a sim feed unless `DATAMASTER_ALLOW_SIM` is set (the market-ingest shape: a simulator reachable by forgetting a flag). `app.tenant_id` is set at the composition root (the accounting bug class), verified against FORCE RLS: the projected row is invisible both to a session with no tenant and to a different one. _Carried forward: `feed.RefSource` still has no implementation, so the pipe is empty — an empty master, not an invented one. The price path stays float64 and therefore has **no** durable price store (DATA-M8b)._

- **EXEC-M7c** — durable order state; the OMS is no longer single-replica-for-correctness. `order.Store`'s only implementation was `MemoryStore`, whose atomicity is a mutex in one process — so `Store.Create`, the atomic admission gate standing between a duplicated `SubmitOrder` and a duplicated venue order, evaporated the moment a second OMS pod existed (two pods, two maps, both `Create` succeed, both route to the venue). `order.Postgres` enforces admission **at the engine** — `INSERT ... ON CONFLICT (tenant_id, order_id) DO NOTHING` with `RowsAffected() == 0 ⇒ ErrExists`, never a `SELECT` followed by an `INSERT` — reusing the risk-engine's `persist` stance (pgxpool, `app.tenant_id` GUC, FORCE RLS under a non-superuser role) rather than inventing a second durable-state pattern. `oms-deploy.yaml` carries `replicas: 2` with the DSN mounted from a CSI/Vault file (SEC-01d), which is the whole point: the guarantee is now cross-pod because it is enforced by a unique index, not by a mutex.

- **EXEC-M7b** — two-tier atomic dedup; the double-trade window is closed. Concurrent redelivery of one event could run its handler twice, and on the order path the handler is *route the order to the venue*. **Tier 1 (`pkg/bus`)**: `Deduper` was `Seen()`+`Record()` — a check-then-act, where two deliveries of one key both passed `Seen` before either `Record`ed. The split existed for a real reason (`Record` ran only after a *successful* dispatch, so a handler failure could not poison the window against retries), and a bare `SETNX` would have destroyed it: claim-and-never-release turns a failed handler into a **lost event**. The contract is now a three-phase lease that keeps both properties — `Claim` (atomic, one `SET NX EX` round-trip, exactly one concurrent winner), `Commit` (success ⇒ hold for the full window), `Release` (failure ⇒ the redelivery really does retry) — with a 5s lease so a worker that dies mid-dispatch has its claim expire rather than swallowing the event forever. Every consumer exit path commits or releases; Redis errors still fail OPEN. **Tier 2 (`services/oms`)**: the bus was never the only hole, and fixing it alone would not have closed this — bus dedup keys on `idempotency_key`, so a re-submit under a *fresh* event id is invisible to it. The OMS's own "idempotent re-submit" guard was `Load()`-then-`Save()`, the same check-then-act, and what runs immediately after it is `s.work()` → `router.Route()` → **the venue**. Two concurrent deliveries both saw `ErrNotFound`, both admitted, and both traded; the state converged (`Save` upserts) so it *looked* idempotent. `Store.Create` is now the atomic admission gate (`ErrExists` ⇒ ack and stop, before the venue). The sharedstate contract test tolerated 25% duplicate leakage on the grounds that idempotent handlers were the real guarantee — **both halves were false**; it now asserts exactly-once and is deterministic (10/10 under `-race`, where it previously leaked 33–60% and flapped). The OMS gained a *concurrent* resubmit test counting real venue executions — the existing idempotency test was sequential, which is why it passed while the bug was live.

- **EXEC-M7a** — the signal→order path could not publish on a real spine. Two independent defects, each of which dropped **every** StrategySignal FACT and SubmitOrder COMMAND on the floor of a live broker. (1) `payload_schema_ref` was never set: `bus.Validate` requires it on every envelope, `Producer.stamp` copied it through verbatim, and no caller on this path supplied one — but this was never `translate`'s bug alone. **Twelve** publish sites across nine files omitted it: the whole signal→order path, every OMS venue connector/recon/userdata emitter, market-ingest's book snapshots, the gateway's order route. Fixed at the **producer**, not at twelve call sites — the ref is not new information (the convention is exactly `{proto full name}:{schema_version}`, and the producer already holds the payload message *and* a `SchemaVersion` that `Validate` independently requires to be ≥1), so it now derives one when the caller omits it, with an explicit ref still winning. A required field the producer can compute itself should never have been the caller's job to remember, and asking twelve callers to remember it is how all twelve forgot. (2) **No JetStream stream was bound to `strategy.>` or `order.>`** — `bus.Publish` is a *JetStream* publish, so an unbound subject is a hard failure, not fire-and-forget. Both now ride the `EXECUTION` stream, added to its subject list rather than renamed under `execution.>` (a rename would break every consumer binding and the replay log's subject history). **Why the suite never caught either:** every unit test on this path injects a fake `capture` Publisher that satisfies the interface and never validates — a fake Publisher cannot fail the way a broker fails. `translate` now carries a real-bus integration test that drives `Emit` through a real Producer over real JetStream and reads both events back; it was verified to fail with the exact production error when the producer fix is reverted.

- **EXEC-M6a/b** — the kill-switch, and the handle to pull it. The `Halted` seam was wired to a **constant `false`** and set by no binary, while `pkg/alpha`'s Runner ticked engines every 100ms with no brake at all — `kill -9` was the risk control. Now one shared **`translate.Gate`**, held by both brains and checked at the webhook perimeter *and* at the top of every alpha tick (engines are not even evaluated while halted — a halted system decides nothing, rather than deciding and discarding). **Deny-by-default**: constructed CLOSED, and only `OPERATING_MODE_NORMAL` trades. **Fail-closed**: a NATS disconnect trips it — `pkg/bus` could not even *observe* a disconnect before (`MaxReconnects: -1` heals silently), so `NATSConfig` gained `OnDisconnect`/`OnReconnect`, with `ClosedHandler` covering the terminal case the disconnect handler misses. **Latching**: reconnection does not clear it and neither can a `system:`-issued ModeChanged; only an operator does — matching `lifecycle.v1`'s own contract that HALTED "requires intervention to leave". The gate is a **required** field in `translate.Options`, because the seam it replaced was optional, defaulted open, and was never wired: an optional brake is an absent brake, and the compiler now refuses to build a translator without one. Keys off the existing **`lifecycle.v1.ModeChanged`** (`component="system"`), NOT a new status enum — a second one would be the parallel system the gate exists to prevent. An undecodable halt FACT trips the gate: "I could not read the brake signal" must never resolve to "keep trading". `cmd/kanz-halt` is the operator's standalone break-glass handle, sharing no code with the trading pipeline (the subject constant lives in a zero-dep `internal/platform/mode` that both ends import) — the one tool that must work while the system is on fire cannot be coupled to the system that is on fire. It rejects `--resume --by system:…` at the flag boundary, since the gate would ignore it and the resume would silently no-op. Verified against a live NATS/JetStream spine, both directions.

- **EXEC-M5b** — the native-alpha boundary (`pkg/alpha`), delivered without a line of alpha math in this repo. **The board's original framing was wrong and the code was ground truth:** publishing a `StrategySignal` FACT onto `strategy.signal.received` executes *nothing* — nothing subscribes to it; it is the audit root, and webhook-ingest fans out the `SubmitOrder` COMMANDs itself in the same call. So the native port had to do both. Rather than clone the fan-out (a second execution path the OMS's pre-trade gates could drift away from), the signal→FACT→commands core was extracted to **`internal/signal/translate`**, now shared by webhook-ingest and native alpha — webhook-ingest's entire test suite passes unchanged over it. `pkg/alpha` is the public boundary the **restricted layer imports as a separate module** (dependency runs private→public; `kanz/go.mod` stays free of a private require): `MarketView` (read-seam — best bid/ask, top-N depth, windowed aggressive buy/sell volume, last price; raw state, no indicators), `Engine`, `Intent`, and a `Runner` that owns the edge. Kanz's own market-ingest runs **the same Runner with zero engines** — it folds and snapshots and decides nothing. The edge internals are re-exported as **type aliases** (`DepthSource`/`Trade`/…) because an external module cannot name a `kanz/internal` type — without them the boundary would compile and be useless; **verified from a real external module** whose only direct kanz import is `pkg/alpha`. New `internal/marketedge/trades`: the trade tape (Binance `@trade`, OKX `trades`, sim), time-bounded, attributing volume by **aggressor** — Binance's `m` flag means *buyer-is-maker*, i.e. a taker SELL, and reading it as a buy inverts every volume-delta signal. `Intent.TimeInForce` carries **IOC** to every leg (an arb leg that rests turns a hedge into naked exposure). Also collapsed the **five** duplicate `dec` packages into one `internal/dec` (the Milestone-5 zero-float consolidation the market-ingest doc anticipated). All four tag combos green; default binaries still vendor-free.
- **EXEC-M5c** — live venue depth reaches the books (`services/market-ingest`). `depth.BinanceSource` (`//go:build binance`, `<symbol>@depth@100ms` diff stream + the `/api/v3/depth` REST anchor) and `depth.OKXSource` (`//go:build okx`, public v5 `books` channel) implement `depth.DepthSource` over the real `coder/websocket` transport; the sim stays the vendor-free default. Each source **owns its resequencing** and normalizes the venue's native chain onto the one rule the book checks: Binance follows the documented procedure (stream first, then REST anchor, drop `u <= lastUpdateId`, first applied event must straddle `U <= lastUpdateId+1 <= u`, then exact `U == prev u + 1`); OKX uses its native `seqId`/`prevSeqId`, skips repeated-`seqId` no-change frames, and resubscribes to re-anchor. Any break **re-anchors on a fresh snapshot** — never an out-of-order fold. Depth is public: no API keys. One book+engine per instrument **per venue** (books never merged; both tags ⇒ two books), which is the shape the cross-venue engine reads. The DNS-bypass dialer was promoted to `internal/exchange/netdial` on the second-consumer trigger — untagged and stdlib-only, so the default binaries of *both* market-ingest and oms remain vendor-free (verified via `go list -deps`); its websocket client carries a zero `Timeout` because `coder/websocket` rejects a client with one and it would kill the long-lived stream. Hermetic tests drive the real websocket over `httptest` and pin the anchor/straddle/gap-re-anchor/zero-size-level/subscribe-error paths on both venues; all four tag combos green.
- **EXEC-M4d** — operational parity closed: the healing seam now has a live writer and runs on both venues. Two halves. (1) **The venue-close dispatch path** — the real gap: `handleCancel` marked an order CANCELLED in the ledger and *never told the exchange*, leaving it resting and still fillable at the venue. New optional `execution.Closer` capability on `Venue` (`CancelOrder`, addressed by our deterministic clOrdId) implemented by `BinanceVenue` (DELETE /api/v3/order; -2011 ⇒ already gone ⇒ confirmed) and `OKXVenue` (POST /api/v5/trade/cancel-order; 51400/51401/51402 ⇒ confirmed); the OMS type-asserts it, **Tracks the `CloseIntent` before dispatch** (the hung-call / ambiguous-timeout / process-death window a post-ack Track would miss), and `Resolve`s on a confirmed withdrawal. An unconfirmed cancel stays tracked for the watchdog and does **not** nack the command — the ledger must never freeze on an unresponsive exchange. A cancelled *resting* order carries no `SweepSide`/`Leaves`: it never traded, so sweeping it would fabricate an opposite-direction position (only a failed position-flatten leaves exposure to sweep). (2) **Binance healing parity** — `Reconciler.RunHealing`/`HealClosures`/`forceSweep` mirroring OKX over the same untagged seam (1500ms timeout, 500ms watchdog tick, query by clOrdId → StateHealed on venue truth, else force-clear + idempotent `heal-`+id market sweep + balance re-anchor), plus `binanceREST.cancelOrder`/`sweepMarket`. The `CloseRegistry` moved to the untagged composition root — one process-wide registry, written by the OMS, drained by whichever venue watchdogs are compiled in. New `CloseTracker` (write) half beside `PendingCloses` (read). Hermetic tests mirror the OKX suite + cover the cancel-never-sweeps invariant and the Closer confirm/surface discipline; all four tag combos green, default binary still vendor-free.
- **EXEC-M4c** — In-Flight Certainty (the healing seam) + production IP hardening (`services/oms`). A close command (cancel / IOC market flatten) races the venue; if its ack stays unconfirmed past a hard 1500ms timeout the ledger must never freeze. Untagged `CloseIntent`/`PendingCloses` seam + in-memory `CloseRegistry` (retry preserves the original timeout clock); the OKX reconciler's `RunHealing` watchdog (500ms tick) queries each due close by clOrdId → `StateHealed` with venue truth if terminal, else force-clears (StateHealed → CANCELLED) and sweeps the residual with an aggressive market order (idempotent `heal-`+id clOrdId, never double-flattens) then re-anchors balances from real venue truth (never fabricated). Wired at `venues_okx.go`. Hardening: Makefile `release` target strips symbols/DWARF + trimpath (`-s -w`, verified `nm`→no symbols, 27→19MB) to resist decompilation; `ErrEgressDenied` types a 401/403 auth-boundary denial (a prod key run outside the exchange IP allowlist) as a non-retryable structural fault; secrets stay memory-only. ### Phase 10 — Product surface (end-user client)

- **PS-02a** — the web BFF (`services/web-bff`): the browser front-of-house over the delivered `/v1` edge, the CLI's browser counterpart. It runs the OIDC authorization-code + PKCE login against Eighred SSO (`internal/oidc`: discovery, PKCE S256, authorize redirect, code exchange), holds the issued token in a server-side session keyed by an httpOnly cookie (`internal/session`: in-memory TTL default with a one-time PKCE-pending store for CSRF/state, clamped to token expiry), and reverse-proxies `/api/*` → gateway `/v1/*` with the server-held bearer attached — never forwarding the browser's cookie or exposing the token to JS. `/auth/login`, `/auth/callback`, `/auth/logout`, `/auth/me`, plus health/ready/metrics; stdlib `net/http`, mirroring the copilot/regulatory service shape. End-to-end tests drive login→callback→proxy and assert the security properties (bearer injected, cookie stripped, unauth 401, forged-state 400, one-time pending). Adds no auth endpoints and no backend analytics; the SSO must register the `kanz-web` client + this BFF's `redirect_uri`, and the gateway validates the JWT via the delivered OIDCAuthenticator.
- **CLI-02** — the `kanz` terminal binary (`cmd/kanz`): a Claude-Code-style REPL that completes the CLI-01 device flow, persists the token (0600, atomic, under `os.UserConfigDir`), renders the KANZ TERMINAL header, and drives turns over the delivered `/v1` edge — natural-language questions through `POST /v1/ask` (answer + citations + refusal/injection/ungrounded warnings) and slash commands (`/exposure`, `/measures`, `/scenario`) through the risk endpoints, plus `/login`/`/logout`/`/whoami`. Auto-runs the device flow on the first turn when no valid token is cached; the bearer is read through a closure so a mid-session `/login` is picked up live. Pure client — talks only to the running gateway (which validates the SSO token via the delivered OIDCAuthenticator); no backend, no mocks. Split into testable `config`/`tokenstore`/`gateway`/`repl` packages; the copilot `/v1/ask` is a single-JSON response (not a stream — the board's "streaming" phrasing was aspirational; ground truth won). Completes the CLI vertical.
- **CLI-01** — the kanz CLI is now an Eighred SSO relying party for the RFC 8628 device-authorization grant: new `pkg/deviceauth` (client-side counterpart to `pkg/auth`'s server-side JWKS validator) resolves the device + token endpoints from the issuer's OIDC discovery document, begins authorization, shows the user_code/verification URI via a caller callback, and polls the token endpoint honoring the server interval + `slow_down` back-off and the `device_code` expiry — returning the issued token for a caller to bearer against the gateway. Adds NO auth endpoints and holds NO keys; identity stays owned by Eighred SSO. Injectable clock/wait keep the poll-cadence + expiry tests deterministic and fast. Unblocks CLI-02.
