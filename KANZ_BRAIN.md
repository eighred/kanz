# KANZ BRAIN

> Living context doc. Last reconciled 2026-05-25 against the architecture docs and KANZ_TASKS.md (Event System + Risk Engine + Prediction Layer (PRED-01..14) + **Data Integrity Layer (DATA-01..11) epics ALL complete**: gap + staleness + watermark/late + drift detectors, NATS↔Kafka reconciliation, quality_flags emission, data-quality event publishing, observability dashboards + alerting, and bad-data + late/reconcile scenario tests. ## Current System Understanding
- Event system is foundation layer
- Risk engine consumes FACT events
- Go handles infra, Python handles inference

## Key Decisions
- Kafka + NATS hybrid architecture chosen
- Envelope-based event design required
- Causality tracking is mandatory
- Modular monolith core (Go) + isolated edge processes for market ingestion, AI inference, and batch compute
- Prediction layer is hybrid: async streaming path (default) + sync gRPC path for interactive calls, with circuit breaker + degraded fallback
- Envelope vs payload schemas are asymmetric: Envelope is additive-only forever (a constitution); payload schemas may break, via a new `vN` package + dual-write migration (EVT-06)
- Payload schemas hold full compatibility (backward + forward) within a package version; backward compat must hold for the full Kafka retention window because replay reads old logs with current code
- Two payload-version fields, not redundant: envelope `schema_version` (uint32) = major version, bumps only on a breaking change, == package `vN`; `payload_schema_ref` registry version bumps on every change incl. additive
- NATS JetStream provisioned as the live spine (EVT-08): one stream per domain (`{domain}.>`), file storage, R3, `limits` retention; retention tiered — 24h hot domains, 7d platform/data, 1h observability, 30d DLQ; 2m dedup window for broker-side idempotency keyed on envelope `idempotency_key`. Replay streams are per-run, not standing (EVT-20)
- Kafka provisioned as the durable log of record (EVT-09): 3-node KRaft cluster (no ZooKeeper), RF3 / min-ISR2, auto-create disabled — topics provisioned explicitly. Topic = `{domain}.{entity}`; retention tiered — 7d high-volume, 30d most FACT/COMMAND, infinite for `platform.model`; `.snapshot` + `platform.config` compacted; a `dlq.{name}` paired with every delete-policy event topic
- New shared proto package `common.v1` (EVT-10): foundational value types every payload schema reuses, owned by event-platform + architecture, evolves under envelope-grade additive-only discipline — prevents cross-domain proto dependencies (e.g. risk schemas importing market). First member: `Decimal` (exact base-10, `coefficient × 10^exponent`); `double` is banned for prices/sizes/money
- Market payload design (EVT-10): `MarketDataEvent` is self-contained (instrument identity + `event_time` inline) so events survive being pulled from a batch; `MarketDataBatch` is per-instrument — all events share one `instrument_id` = envelope `partition_key`, ordered by non-decreasing `event_time`, so per-partition ordering still holds
- Domain/state payload design (EVT-11): `PortfolioState`/`PositionState` are aggregate-level state payloads — portfolio does NOT embed positions (those are their own events); `PortfolioSnapshot` is the STATE_SNAPSHOT and carries a `LogPosition` for gap-free bootstrap; exposures are emitted as a coherent `ExposureSet`, never piecemeal. `common.v1` gained `Money` (Decimal + ISO 4217) and `LogPosition` (durable-log coordinate)
- Command layer design (EVT-12): `command.v1` is the generic command layer — what `envelope/v1` is to events. `CommandMetadata` (issuer, target, valid_until, reason) is embedded as field 1 by every concrete domain command; `command.v1` holds no domain-specific command body and no `Any` wrapper, so each concrete command keeps its own `payload_schema_ref` for clean registry tracking. `CommandOutcome` is the single universal outcome-FACT payload; the command it reports on is identified by envelope `causation_id`, not restated
- Payload timestamp convention (clarified EVT-13): a payload restates a domain timestamp only when events can be bundled under one envelope (batch/snapshot) so a single envelope `event_time` cannot represent them all — `MarketDataEvent.event_time`, `PositionState.as_of`. Standalone, never-bundled events (lifecycle FACTs) omit the timestamp; envelope `event_time` is authoritative. They still carry a principal (`*_by`) because envelope `source` is the emitting service, not the acting principal
- Observation payload design (EVT-14): general observations (`MetricObservation`, `DecisionLog`) are lossy-tolerant; `DataQualityEvent` is one schema with a `oneof` over gap/staleness/drift plus common triage fields (subject, severity, summary) so data-observability handles it generically, and it is FACT-grade despite `EVENT_CLASS_OBSERVATION` (the documented exception). Late data is an envelope `QualityFlag`, not a `DataQualityEvent` kind. `double` is fine for metrics and statistical drift scores — the exact-`Decimal` rule is specifically for money/prices/sizes
- Codegen pipeline (EVT-15a): generated code is never committed to `kanz-schemas` (gitignored, decided EVT-01). A tag-triggered `schema-release.yml` runs `buf generate` and publishes each language SDK as its own artifact. Go → companion module repo `github.com/kanz-eng/kanz-schemas-go`, committed + tagged by CI in lockstep with `kanz-schemas` releases. `.proto` files carry no `option go_package`; buf managed mode supplies it. Python (EVT-15b) and TS (EVT-15c) extend the same `buf.gen.yaml` + release workflow
- Python SDK (EVT-15b): uses buf.build **remote** plugins (`protocolbuffers/python` + `pyi` for stubs) — no clean standalone local plugin exists for Python, unlike Go. Published as the `kanz-schemas` package to a package index (PyPI or a private index via `PYPI_REPOSITORY_URL`), not a companion git repo. Package metadata is the versioned template `packaging/python/pyproject.toml`; CI injects the release version and adds the `__init__.py` files protoc-gen-python omits
- TypeScript SDK (EVT-15c): uses the buf-maintained `bufbuild/es` remote plugin (Protobuf-ES) with `target=js+dts` so the generated tree is ES modules + `.d.ts` declarations — no separate `tsc` step. Published as the scoped `@kanz-eng/kanz-schemas` package to npm (or a private registry via `NPM_REGISTRY_URL`); scope matches the `kanz-eng` org, `--access public` set so the scope still publishes openly. Template `packaging/ts/package.json` uses a wildcard `exports` map (`./*: ./*`) so consumers import per-file (`@kanz-eng/kanz-schemas/envelope/v1/envelope_pb.js`) without a hand-maintained barrel
- Go module layout (EVT-16a): single Go module rooted at `kanz/` (`github.com/kanz-eng/kanz`, Go 1.23), all services and shared packages live under it. Services are `package main` in `services/<name>/cmd/<name>/`; shared internal packages live under each service's `internal/` (per-service first, promote to top-level `kanz/internal/` or `kanz/pkg/` only when a second consumer appears). Stdlib `net/http` + `log/slog`; only direct external dep so far is `pgx/v5` for Postgres
- Schema registry storage (EVT-16a): one row per (`schema_id`, `version`) in Postgres `schemas` table — immutable once published per kanz-schemas/docs/schema-evolution.md §6. `Storage` interface (`Put` / `Get` / `Ping`); `Put` is idempotent — same `(ref, descriptor)` succeeds, different descriptor under existing ref returns `ErrConflict` (via `INSERT ... ON CONFLICT DO UPDATE SET source_tag = schemas.source_tag RETURNING fingerprint` to fetch the existing fingerprint in one round-trip). `descriptor` is opaque `BYTEA` — the registry doesn't decode it; format is the ingestor's contract (EVT-16b). Schema-ref wire form `<schema-id>:<version>` (e.g. `market.v1.MarketDataEvent:7`), parsed by `storage.ParseRef`. In-memory `Memory` backend ships alongside `Postgres` so the same test suite runs without a database
- Schema registry ingest (EVT-16b): the **registry assigns versions**, not the caller — `Storage.Register(schemaID, descriptor, sourceTag) → (Ref, created, err)` looks up the latest stored row for `schemaID`; same sha256 fingerprint ⇒ idempotent return of that ref with `created=false`; new content ⇒ insert at `latest+1` with `created=true`. Postgres impl uses a Serializable transaction since rare ingest correctness beats throughput. HTTP wire: `POST /schemas/{schema_id}` with raw FDS subset body + `X-Source-Tag` header; `200` vs `201` distinguishes idempotent from new. Per-message granularity is the *ingestor's* choice — the kanz-schemas tool slices the global FileDescriptorSet into one subset per top-level message (file + transitive imports), so each registry row is a self-contained FDS that `protoc --descriptor_set_in` can consume directly. Tool lives in `kanz-schemas/tools/registry-ingest/` as its own tiny Go module (only dep `google.golang.org/protobuf`) so kanz-schemas's CI doesn't pull in the kanz monorepo
- Schema registry resolve (EVT-16c): `GET /schemas/{ref}` — `ref` is the literal `payload_schema_ref` string (`<schema-id>:<version>`), placed unencoded in a single path segment since `:` is RFC-3986-legal there and Go's stdlib mux passes it through `r.PathValue` intact. Response body is the **raw descriptor bytes** (`application/octet-stream`), not JSON-with-base64 — descriptors are read on hot paths and base64 inflates by 33%. Metadata travels in `X-Schema-*` headers (`Fingerprint`, `Source-Tag`, `Created-At`) so consumers can read it without parsing the body. Because `(schema_id, version)` is immutable once published, responses ship `ETag: "<fingerprint>"` + `Cache-Control: public, max-age=31536000, immutable` — any HTTP cache, proxy, or client can hold the answer forever. Register also tightened: `schema_id` containing `:` now `400`s, keeping resolve URLs unambiguous
- Bus client foundation (EVT-17a): `kanz/pkg/bus` exposes a *single* `Client` interface (`Publish` + `Subscribe` + `Close`) implemented by both `NATSClient` and `KafkaClient` — EVT-17b–e (envelope stamping, trace propagation, dedup, DLQ) layer over either transport uniformly rather than reimplementing per backend. Library picks: `github.com/nats-io/nats.go` (JetStream v2 API) and `github.com/segmentio/kafka-go` (pure-Go, no cgo) — `kafka-go` chosen over `franz-go` and `confluent-kafka-go` because cgo-free builds matter for the kanz container images and 17a's needs are basic enough that the simpler API wins. Kafka writer pins `Hash` balancer (partition-by-key), `RequireAll`, `AllowAutoTopicCreation=false` (per EVT-09 the topics-job owns provisioning), and Snappy. Per-message manual commit on the Reader so EVT-17e can own retry/DLQ semantics without fighting auto-commit. `Message.Key` round-trips natively over Kafka; over NATS (no native key) it rides as a `Kanz-Partition-Key` header that the receive path strips from the user-visible `Headers` map. Handler returns nil ⇒ ack/commit; non-nil ⇒ nak (NATS) / skip-commit-redeliver (Kafka). Bus client does *not* manage streams or topics — those stay in `kanz/infra/{nats,kafka}/`
- Wire framing (EVT-17b): every bus message body is a serialized `envelope.v1.EventFrame { Envelope envelope = 1; bytes payload = 2 }`. Sibling layout (not nesting `bytes payload` inside `Envelope`) was chosen so payload-blind tooling — schema registry, observability, replay, routing — can decode the envelope without bringing in the payload schema. EventFrame lives in `envelope/v1` because the framing is a universal envelope-platform concern; adding it is non-breaking (new sibling message in the package, no Envelope change, no `envelope_version` bump per envelope-policy §6). Producer/Subscriber wrappers serialize/deserialize the frame; the underlying `Client` stays bytes-only
- Stamping + validation (EVT-17b): `Producer` over a `Client` owns the publish-side rules. Auto-stamped: `event_id` (UUIDv7, time-sortable), `publish_time` (now), `ingestion_time` (defaults to now), `correlation_id` (defaults to `event_id` on roots), `envelope_version` (constant `1` for now), `source` + `producer_version` (from `ProducerConfig`), `producer_sequence` (per-(event_type, partition_key) monotonic counter under a mutex — 0 when partition_key is empty), `idempotency_key` (= `event_id` for FACT/STATE_SNAPSHOT/OBSERVATION; caller-supplied for COMMAND, rejected if missing). `Validate` is exported and reusable on the consumer receive side; it enforces every required-field rule in envelope-policy §7 + the FACT idempotency invariant + the live-publish prohibition of `QUALITY_FLAG_REPLAYED` (replay sets this; live publishers must not). Caller-set `IdempotencyKey != event_id` on a non-COMMAND event is a stamping error, not silently overwritten. `Unframe` is the consumer-side helper
- Go module dependency on schemas (EVT-17b): `kanz` requires `github.com/kanz-eng/kanz-schemas-go` (the Go SDK published by `schema-release.yml`). Until the first kanz-schemas release tag, dev/CI use `replace github.com/kanz-eng/kanz-schemas-go => ../kanz-schemas/gen/go` after running `buf generate` + `go mod init` in `kanz-schemas/gen/go/`. The `replace` line is the marker to strip once a tagged release exists. New deps in `kanz/go.mod`: `google.golang.org/protobuf`, `google/uuid` (UUIDv7)
- Lineage propagation (EVT-17c): `correlation_id`, `causation_id`, `trace_context` ride `context.Context` between handler and downstream publish — not function parameters — so a typical "receive → do work → publish derived event" path threads lineage with zero hand-coding. Three unexported `ctxKey` slots populated by `bus.With{Correlation,Causation,Trace}…` helpers; `Consumer` stashes them automatically on receive. Key subtlety: `causation_id` stashed under the *next* event's slot is the **current** event's `event_id` (not the current event's `causation_id`) — that's how the chain links. Precedence on publish is **explicit Event field > ctx-derived > root default**: explicit values always win, so a producer that wants to break the chain (e.g. emit a true root event from inside a handler) just sets `Event.CorrelationID` explicitly. Empty `trace_context` is not stashed (avoids overwriting an existing ctx value with empty). `Consumer` also runs `Validate` on every inbound envelope — defense-in-depth and lets EVT-17e's DLQ catch malformed messages once it lands
- Dedup (EVT-17d): two reinforcing layers, not one. **Publish side** — Producer stamps `Nats-Msg-Id: <idempotency_key>` on every outbound `bus.Message`; NATS JetStream keys its broker-side dedup window on this header (EVT-08's 2m window). Kafka carries it as a regular user header (harmless). One header serves both transports because NATS reserves the name and Kafka is name-agnostic — the alternative of defining our own header and translating in NATSClient added complexity for no gain. **Consumer side** — bounded sliding `DedupWindow` keyed on `idempotency_key`, default 2m / 10k entries (TTL matches NATS so the layers reinforce: a duplicate that slips broker dedup is caught by consumer dedup; a duplicate within window is caught by either). Split API (`Seen` / `Record`) lets `Consumer.Subscribe` record **only after a successful dispatch** — a transient handler failure must remain retry-able. Two concurrent deliveries of the same key can both pass `Seen` before either `Record`s, so handlers must be idempotent (event-class-rules §1) — the window is a perf optimization, not a correctness primitive. Dedup is **per-instance, in-memory**; cross-pod dedup is explicitly out of scope (cross-pod redelivery is handled by idempotent handlers, not by sharing the window through a store). `NewDedupWindow(0, …)` or `(…, 0)` returns nil; methods are nil-safe so the disabled path needs no nil-checks at every call site. Eviction is lazy GC of expired entries first, then oldest-evict if still at capacity
- Retry + DLQ (EVT-17e): bounded retry happens **inside** the Consumer's dispatch — `RetryConfig.MaxAttempts` loop with exponential backoff (no jitter at this layer; capped at `MaxBackoff`; sleep is ctx-cancelable). Tradeoff: this blocks the partition for the retry sequence; high `MaxAttempts` × long backoff trades throughput for resilience. The alternative (retry by re-publishing to a delay topic) was rejected for 17e because it needs delay-queue infra Kafka doesn't have natively — revisit if partition stall becomes an operational issue. **DLQ subject convention**: `dlq.<original-subject>` (matches the `dlq.>` NATS stream and the `dlq.{name}` Kafka topics already provisioned in EVT-08/09). DLQ pre-dispatch failures (`Unframe`/`Validate`) are routed too, with `Kanz-DLQ-Attempts: 0` — payload was never run. Body and original headers (incl. `Nats-Msg-Id`) are passed through unchanged so investigators can re-parse the frame and DLQ consumers can dedup if they wish. Three load-bearing details: (1) DLQ publish failure surfaces — the broker re-holds the message, never lose poison events; (2) DLQ success records the idempotency_key in dedup so subsequent duplicates of the same poison skip (terminal); (3) `WithRetry` and `WithDLQ` are independent — DLQ-without-retry is "first failure is poison", retry-without-DLQ is "bounded attempts then surface to broker"
- EVT-17 epic complete: the Go bus client is end-to-end runnable as of EVT-17e — `Producer`+`Consumer` over either `NATSClient`/`KafkaClient` give a service the full stamp → validate → publish → subscribe → unframe → validate → dedup → retry → DLQ pipeline. Python (EVT-18) and TS (EVT-19) clients are next; they must match this contract on the wire (`EventFrame` framing, `Nats-Msg-Id` header semantics, dedup `idempotency_key`, DLQ subject prefix + `Kanz-DLQ-*` headers, ctx-style lineage propagation in whatever each language's idiom is)
- Python bus client foundation (EVT-18a): new `kanz-py/` tree, package name `kanz-bus` on PyPI, importable as `kanz_bus`. Async-first throughout — `nats-py` and `aiokafka` are both asyncio-native, so the public API is `async def`-everywhere with `async with` context-manager lifecycle and `asyncio.CancelledError` as the cancel signal (mirroring Go's ctx-cancellation). Kafka library pick: **aiokafka over confluent-kafka-python** — aiokafka is pure-Python (no librdkafka cgo dependency), single asyncio event loop, matches the rest of the Python stack; confluent-kafka offers higher perf but its thread-pool model fights asyncio and ships a C dependency. Wire compatibility with the Go client is the load-bearing constraint: `Message {subject, body, key, headers}` shape matches `bus.Message`; the same `Kanz-Partition-Key` header bridges `key` over NATS (since NATS has no native key) and is stripped on receive. NATS uses **pull-subscribe** with a fetch-loop (durable per (subject, group)) rather than callback-based push, so cancellation is clean — a timeout cycle lets `CancelledError` propagate quickly. Kafka uses per-Subscribe `AIOKafkaConsumer` (one consumer per call) with `enable_auto_commit=False` so EVT-18d can own retry/DLQ. Test layout: tests live in `kanz-py/tests/` (outside the package so they don't ship in the wheel); `asyncio_mode = "auto"` in pyproject means async test funcs don't need explicit decorators
- Python stamping + validation (EVT-18b): wire-identical to Go EVT-17b — same `envelope.v1.EventFrame` framing, same `Nats-Msg-Id` broker-dedup header, same per-(event_type, partition_key) monotonic `producer_sequence`, same `idempotency_key` derivation rules per event class. `Producer` is sync-safe within a single asyncio event loop without a lock: `_next_sequence` is a regular method, no `await` inside, so its dict read-modify-write is atomic under asyncio's cooperative scheduling — adding `asyncio.Lock` would be ceremonial. **UUIDv7 implemented inline** (~10 lines bit-packing) rather than pulling in `uuid_utils` or `uuid-extensions`: stdlib `uuid.uuid7` arrives in Python 3.13 but the package floor is 3.10, and the inline implementation matches RFC 9562 exactly. `validate(env)` raises `ValueError` (Python idiom) where Go returns error — same rules, same error messages where practical for cross-language log grepping. **kanz-schemas Python SDK dep**: pyproject declares `kanz-schemas>=0.1.0`; until the first release, dev uses `pip install -e ../kanz-schemas/gen/python/` after `buf generate` (analogue of the Go `replace` directive). `protobuf>=5.29` pinned to match the schema-release CI's generated-code expectations
- Python lineage propagation (EVT-18c): the Python idiom for "thread something across `await` boundaries without an explicit parameter" is `contextvars.ContextVar` (PEP 567) — asyncio copies the Context across await within a coroutine and snapshots into newly-created tasks, so propagation just works. Three module-level contextvars in `kanz_bus.propagation`; primary API is a `@contextmanager` `propagation_context(*, correlation_id, causation_id, trace_context)` that sets only non-empty fields (empty values must not clobber an outer-context value — same "non-empty only" rule as Go's `WithTraceContext` skip on empty). **`EventHandler` deliberately has no explicit ctx arg** — `Callable[[Envelope, bytes], Awaitable[None]]`. Lineage is implicit. This is the right Python idiom but trades the Go ergonomic of "look at the function signature to see what's threaded"; the README and module docstring make the implicit threading explicit. `Producer.stamp` precedence stays the same as Go: explicit `Event` field > contextvar > root default. Same load-bearing subtlety: the `causation_id` stashed for the *next* event is the **current** event's `event_id` (not its causation_id) — that's how the lineage chain links
- Python dedup + retry + DLQ (EVT-18d): the Python plan **combined** what Go split into EVT-17d (dedup) and EVT-17e (retry+DLQ) into one subtask — same underlying behaviour, less ceremony. `DedupWindow` uses a "disabled-mode instance" instead of nil (Python's analog of Go's nil-safe receiver) — pass `DedupWindow(ttl_seconds=0)` to get a no-op instance, so `Consumer` always has a usable `_dedup` reference and never needs to nil-check. `RetryConfig` uses a dataclass with sensible defaults plus a fallback on the `backoff()` method for zero-field-value cases. `ConsumerConfig` is a single dataclass holding the three independent options (`dedup_window`, `retry`, `dlq`) rather than functional-option-style — more idiomatic Python and discoverable in IDEs. **`asyncio.CancelledError` is re-raised** out of the retry loop without being swallowed by `except Exception` — critical for the broker shutdown path. Same Go-side wire contract: `Nats-Msg-Id` header for broker dedup (set in Producer, EVT-18b), `dlq.<subject>` topic convention, `Kanz-DLQ-{Original-Subject,Attempts,Error}` headers. EVT-18 epic complete: the Python client is now end-to-end runnable, wire-compatible with Go EVT-17, and reading the same envelope frames the schema-release pipeline publishes
- TS lineage propagation (EVT-19c): `withPropagation(ctx, fn)` is a *function-taking wrapper* — not a context manager or decorator — because Node's `AsyncLocalStorage.run(store, callback)` already binds the store to a callback's lifetime, so the natural TS API mirrors that shape directly. Same "empty fields don't overwrite outer" rule as Go's `WithTraceContext` skip-on-empty and Python's `propagation_context` partial-set: per-field `next = explicit || outer || ""`. Computed eagerly into a fresh store, not lazily — keeps `getCorrelationId/CausationId/TraceContext` cheap (single store read, no merging at read time). **`AsyncLocalStorage` propagation rules**: stores carry across `await`, `Promise.then`, `queueMicrotask`, and `setTimeout` callbacks within the same async chain because Node's async_hooks copies the store on async resource creation — that's the TS-side guarantee that maps to Python's `Context.run`-on-task-creation semantics and Go's ctx-passed-explicitly model. **`EventHandler` has no explicit ctx arg** — `(Envelope, Uint8Array) => Promise<void>` — matching the Python idiom. The TS-vs-Go tradeoff: callers lose the "look at the signature to see what's threaded" property Go provides, but gain the no-ctx-plumbing ergonomic that's expected in Node code. The README and module docstring make the implicit threading explicit. **Consumer scope deliberately stays EVT-17c, not EVT-17e**: the task board's EVT-19 plan only has `a/b/c` (foundation, stamping, propagation) — no `19d/19e` for dedup/retry/DLQ. So `Consumer.subscribe` is `unframe → validate → withPropagation → dispatch`; pre-dispatch errors throw out, the underlying NATS/Kafka client triggers redelivery via nak/skip-commit, and handler-side idempotency (event-class-rules §1) is the only correctness primitive. If TS later needs dedup/retry/DLQ, the Consumer would gain the same composable options shape as the Python `ConsumerConfig` from EVT-18d (combined dedup/retry/DLQ into one subtask). Same Go-side load-bearing subtlety carried forward: the `causationId` stashed for the *next* event is the **current** event's `eventId` (not its `causationId`) — that's how the chain links. **End-to-end Consumer→Producer chain test** is the load-bearing integration test: OneShotSub feeds an inbound envelope, Consumer stashes lineage, handler calls Producer.publish, CaptureClient asserts the outbound envelope inherited correlation/causation/trace without the handler touching them
- TS stamping + validation (EVT-19b): wire-identical to Go EVT-17b / Python EVT-18b — same `envelope.v1.EventFrame` framing, same `Nats-Msg-Id` broker-dedup header, same per-(event_type, partition_key) monotonic `producerSequence`, same `idempotencyKey` derivation rules per event class. Field-naming is the load-bearing language-translation detail: Protobuf-ES v2 converts every snake_case proto field to camelCase on the generated TS type, so the *wire* stays `producer_sequence` while the TS-side accessor is `producerSequence` — Validate / Producer have to match the TS shape. Bigint integers: uint64 fields (`producerSequence`) become `bigint` in Protobuf-ES v2 (uint32 stays `number`), so the "sequence must be 0 when partition_key empty" check is `=== 0n`, and the sequence Map stores `bigint`. **Async-safe sequence counter** — same reasoning as the Python client: read-modify-write of the Map runs synchronously without `await` inside `nextSequence`, so Node's cooperative scheduling guarantees atomicity; no `Mutex` needed (Node has no equivalent of Go's `sync.Mutex`, and stdlib offers no async lock primitive — relying on the no-await invariant is the idiomatic move). **UUIDv7 inline** (~10 lines via `node:crypto`'s `randomBytes`) rather than pulling in `uuid` or `uuid-with-v7`: Node 24's `crypto.randomUUID` is v4-only, and we need v7's time-sortable property for `event_id` to drive natural ordering. Same RFC 9562 bit layout the Python client uses. **PayloadWithSchema descriptor pattern**: Protobuf-ES v2 separates the runtime descriptor (`DescMessage`, e.g. `EnvelopeSchema`) from the message instance (`MessageShape<Desc>`, e.g. `Envelope`) — unlike Go's pure proto.Message reflection or Python's bound `Message.SerializeToString()`. `Event.payload` is `PayloadWithSchema<Desc>{schema, message}` so `Producer.publish` can call `toBinary(schema, message)` with full type safety. Slight extra ceremony at the call site vs Python's `payload=msg` but typed correctly. **Lineage getters stubbed in EVT-19b, setter API in EVT-19c**: `propagation.ts` exposes `getCorrelationId/CausationId/TraceContext` backed by `AsyncLocalStorage<PropagationContext>` (Node's `node:async_hooks` analog of Python contextvars / Go context.Context). EVT-19b's Producer reads these getters so the publish path auto-inherits any lineage already on the async store; EVT-19c adds the `withPropagation`-style setter + Consumer integration that actually stashes inbound envelope fields. Same staged approach the Python client used (propagation.py imports landed in EVT-18b producer.py, full contextvar API + Consumer integration in EVT-18c). **kanz-schemas TS SDK dep**: pyproject analog declares `@kanz-eng/kanz-schemas: ^0.1.0` + `@bufbuild/protobuf: ^2.2.3`; until first release, dev uses an npm workspace or `npm install ../kanz-schemas/gen/ts` (analog of Python's `pip install -e ../kanz-schemas/gen/python/` and Go's `replace` directive). `validate` throws `Error` (TS idiom) where Go returns error and Python raises `ValueError`; error messages stay parallel across languages for cross-language log grepping
- Replay flag + bidirectional validator (EVT-20c): the original `bus.Validate` (EVT-17b) baked the REPLAYED-rejection into a single function, which was the right default for a codebase with no replay layer yet but blocked replay consumers from ever accepting the flag once the layer landed. - Watermarking + late-data routing (DATA-03): `WatermarkTracker.Observe(env)` keeps a per-stream watermark = `(max event_time seen) - AllowedLateness` and flags an event LATE when its event_time falls below it. **Lateness ≠ staleness — the two integrity signals are orthogonal and both live in this package now**: DATA-02 staleness is one event's ingestion lag (how old the data was when Kanz received it — source freshness); DATA-03 lateness is an event's position relative to the stream's *event-time progress* (did it arrive after the consumer already closed the window its event_time belongs to — ordering/completeness). - Feature-store boundary (PRED-11): the interface inference paths read materialised features through (`kanz_inference/featurestore/`), with a trivial in-memory impl. **Lands-before-impl, deliberately ahead of any consumer**: both paths today already receive a full FeatureVector (streaming decodes `inference.feature.computed`; interactive gets the gRPC body), so nothing reads from a store yet — the boundary is pinned first (same pattern as PRED-04's `Model`/`PredictionPublisher`, RISK-04's `Applier`) so a real store (Feast online store, Redis, DynamoDB, a point-in-time warehouse) plugs in behind it without touching callers, and PRED-12's schema-versioning contract tests get a target. **Point-in-time `get(subject_id, feature_set_ref, as_of)` is THE load-bearing decision** — returns the vector effective AT OR BEFORE `as_of`, never a later one. This is the single property separating a feature store from a cache: a "latest value wins" store would silently leak future data into replay/backtest (breaking the EVT-21d-style determinism the rest of the platform guarantees) and create training/serving skew (offline training joins as-of label time; online serving must match). A store ignoring as_of is cheaper and looks correct in a live-only demo, then corrupts every backtest — so the boundary forces the honest contract on every impl. `as_of=None` ⇒ latest; `as_of` before all stored marks ⇒ `None` (rather than leak the future), and per PRED-02 the caller treats a miss as missing-features → DEGRADED, not zero features. **Keyed by `(subject_id, feature_set_ref)` jointly** — a subject carries features under several feature sets simultaneously (different models read different sets), so feature_set_ref is part of identity not just routing; same key the registry + worker route on. **Async-everywhere** to match the eventual remote-store contract + the `Model` protocol; the trivial impl never awaits so it's lock-free under the single event loop (same reasoning as PRED-04's `LastKnownCache` and the PRED-08 admission counter). **Ordering via `(seconds, nanos)` tuple** (proto Timestamps aren't directly orderable, no float round-trip) + `bisect` over a parallel sorted-keys list: `put` inserts keeping history sorted so out-of-order puts still resolve correctly, `bisect_right(target)` finds the rightmost at-or-before entry. **`put` idempotent-by-as_of**: same as_of overwrites (re-materialise one point in time), new as_of extends history. **Defensive `CopyFrom` on both put and get** so caller mutation can't bleed into stored state or vice versa — RISK-03 immutability discipline carried to Python. **Trivial impl deliberately omits**: persistence (process-local dict), TTL/eviction (unbounded), online/offline split, distributed state — each is a real-store concern behind the same `get`/`put` contract, same "three deliberate omissions keep the surface tight" stance as the PRED-09 registry. pyproject needs no change — `kanz_inference*` already auto-discovers the new subpackage
- Shadow / canary executor (PRED-10): satisfies the Model protocol by wrapping PRED-09's Registry — workers (PRED-04 streaming, PRED-08 interactive) use it in place of a bare Model and gain transparent shadow fan-out without any worker-side shadow code. **Shadows run AFTER the primary, not in parallel — the load-bearing decision**. Alternative considered: asyncio.gather(primary + shadows) for max parallelism. Rejected because gather's completion is bounded by the slowest task, so a slow shadow would directly push out the primary's latency — defeating the canary's "risk-free evaluation" premise. Sequential primary-first + fire-and-forget shadows keeps the served-response latency budget tracking ONLY the primary; shadow throughput affects only background work. Trade-off: a shadow depending on state the primary's execution side-effected (cache warmup, GPU memory pre-allocation) sees different behavior than it would in true parallel. Accepted because any such coupling indicates a stateful Model implementation, which itself violates PRED-04/08's per-call model contract — flag it there, not work around it here. **Shadow failure isolation is structural**: each shadow's `predict` AND each observer's `observe` are wrapped in try/except inside `_run_shadow_and_observe`; exceptions logged but never re-raised. By the time a shadow CAN fail, the primary's response has already returned to the caller — there is no code path by which a shadow exception affects what the consumer sees. This is what makes canary truly risk-free in the live serving path. **Task tracking via `_shadow_tasks` set + `add_done_callback(discard)`** prevents Python's GC from reclaiming fire-and-forget tasks before they complete. Without this, asyncio.create_task references would be the only thing holding the task alive — if the executor variable went out of scope mid-task, the task would silently die. The set also enables `wait_for_shadows()` for graceful shutdown (drain before exit) and deterministic test completion (without it, tests would race between predict-return and shadow-completion). **Routing by `fv.feature_set_ref` at predict time**: one ShadowExecutor per process handles every feature_set the worker receives. Alternative (one ShadowExecutor per feature_set, bound at construction) would force the worker to maintain a map and dispatch — duplicating routing logic across consumers. Centralizing it in ShadowExecutor matches the registry's "lookup is the routing primitive" design from PRED-09. **`model_id = "shadow-executor"` composite** is the honest answer when ShadowExecutor routes across many models — there is no single canonical id. Per-response `PredictionEnvelope.model` carries the actual primary's id for traceability (set by the primary's `predict`). Workers' degraded fallback paths stamp the composite id in synthesized envelopes; slight imperfection but acceptable for the cache-miss edge case. **`ShadowObserver` Protocol with `@runtime_checkable`** + async `observe(fv, primary_meta, primary_pred, shadow_meta, shadow_pred)`. Async signature so remote sinks (metrics push, database write, observation.v1.DecisionLog emission) don't block the shadow path. Default `LoggingShadowObserver` logs each pair at INFO with the delta — fine for low-volume canary; high-volume production swaps for a metrics-store observer. **No primary for feature_set_ref → DEGRADED with `inference_unavailable`**: same identifier PRED-04/08 use for the same operational state (inference layer cannot serve this route). Reusing the identifier keeps observability consistent across paths

- Model registry (PRED-09): the versioned lookup surface both inference paths (PRED-04 streaming, PRED-08 interactive) call when they need a Model to score against; also the registration point for PRED-10's shadow/canary path. **Explicit primary/shadow distinction at registration time is the load-bearing decision**: two models can serve the same feature_set_ref simultaneously — the PRIMARY produces the response consumers see, SHADOWS run in parallel for evaluation (PRED-10). Alternative considered: single flat map of model_id → Model, callers pick the "right" one. Rejected because it spreads routing policy across every caller — every worker would need its own "which model is active for this feature_set" rule, and they'd drift apart over time. Concentrating the role decision at `register(metadata, model, primary=True/False)` puts policy in one place and gives workers two intent-revealing lookup methods (`primary_for_feature_set` for the served response, `shadows_for_feature_set` for fan-out). **Three internal indexes redundantly maintained** (`_by_id`, `_primary_for_fs`, `_shadows_for_fs`): keeps both lookups O(1) without iterating. Memory cost is trivial (one model_id string per entry); cost-vs-benefit clearly favours the redundancy. **Re-registering an existing model_id replaces the entry** (hot-reload pattern for artifact updates); `_remove_from_role_indexes` scrubs the old role first so a "primary → shadow" demotion is consistent. Without this, a model that was primary for fs-X and gets re-registered as shadow for fs-X would still appear as primary in the index. **`ModelLoader` Protocol abstracts artifact loading**: the registry stores CONSTRUCTED Model instances; how artifact_uri becomes a Model is a deployment concern that plugs in via this protocol. Loading semantics differ wildly across model formats (pickle, ONNX, torchscript, joblib, remote inference server); putting format-specific code in the registry would tightly couple it to whichever format ships first. Loader is optional — callers can construct Model instances any way and register them; the protocol is there for when a pluggable loading abstraction is useful. **`ModelMetadata` frozen dataclass with `confidence_threshold` per-model**: PRED-02 §2.3 explicitly forbids a global confidence threshold — different models have different calibrations (a high-conviction signal model at 0.8 vs probability-of-default at 0.3). The threshold travels with the model artifact (set by the model owner, recorded here) so the inference path applies the right cutoff without per-model branching in worker code. Uncalibrated models set `confidence_threshold = 1.0` — every prediction is below, every prediction marks DEGRADED per the "unknown confidence as no confidence" rule. **Validation at register time** (model_id format `@`-required, feature_set_ref format `:`-required, both non-empty, model non-nil): registry rejects malformed inputs at the point of registration rather than failing later at lookup or worker-call time. Strict format-parsing deferred — for now the contains-character checks are enough to catch the common bugs (forgotten version, swapped @/:, empty string from a config-loading bug). **What the registry deliberately does NOT do**: artifact LOADING (deferred to ModelLoader), lifecycle (warmup, LRU eviction — long-running worker keeps everything in memory; PRED-09b can add eviction if memory pressure becomes real), DISTRIBUTED state (each worker process has its own registry; cross-process coordination is config management + rolling restarts, not a runtime registry concern). Three deliberate omissions keep the surface tight; each can land as a follow-up when the use case is concrete

- Python interactive servicer (PRED-08): the gRPC server side of the interactive sync path — PRED-07's Go client targets this. With PRED-08 shipped, both prediction paths are end-to-end runnable: streaming (Go publishes feature events → Python worker drains → publishes predictions back) and interactive (Go sync client → gRPC → Python servicer → response). **Counter-based admission control over asyncio.Semaphore is the load-bearing decision**: Semaphore's `acquire()` blocks indefinitely, defeating "fail fast on overload" — the whole point of admission control is to REJECT, not queue. Counter-with-immediate-reject gives exact "in_flight ≥ max ⇒ reject now" semantic. Race-free under asyncio (single event loop, no await between read and increment) — same reasoning as PRED-04's no-Lock-on-cache decision. The simplest correct primitive for the problem. **`pool_saturated` added to PRED-02 §2.1** as a fourth identifier under the "inference unavailable" trigger category. Additive doc edit — same shape as the existing `inference_unavailable`/`bus_lag_exceeded`/`circuit_open`. Distinct from generic `inference_unavailable` so observability can distinguish "overload" (scale up, add workers) from "downstream failure" (model server crashed, debug the artifact) — different alert routes for different operational responses. Same alert-stability discipline as the other identifiers: named constant, not free-form string. **Process isolation from streaming worker is structural** per KANZ_BRAIN anti-decision: market ingestion, AI inference (this), batch compute must be process-isolated. PRED-08's servicer runs in its OWN process — not co-located with PRED-04's streaming worker. Admission rejections show up as DEGRADED responses (not bus consumer-lag piling up), which preserves the isolation contract: streaming bursts cannot starve interactive responses and vice versa. The shared model artifact (loaded by both processes from PRED-09's registry) ⇒ same scoring logic on both paths ⇒ replay-determinism between paths. **Cancellation propagation, not catch-and-synthesise**: when the client (PRED-07) deadline expires, the gRPC framework cancels the server-side coroutine. The servicer catches `asyncio.CancelledError` only to let the `finally` block decrement in_flight, then re-raises — synthesising a response would be wasted work since the client isn't listening. PRED-07 translates the client-side DEADLINE_EXCEEDED to a DEGRADED envelope with `inference_timeout`. Server-side timeout would race the client deadline, so deliberately omitted; if a client misuses the API and forgets to set a deadline, the call runs to completion and the operational signal is "look at request duration metrics" rather than "silently capped at some hidden value". Honest behavior over defensive magic. **`finally` decrements in_flight uniformly**: success, exception, cancellation all release the slot. Without this, a model that occasionally raises would slowly leak slots until the servicer permanently advertises as saturated — the kind of bug that takes hours to diagnose in production. **`serve(model, address, max_in_flight)` helper** handles the boilerplate of constructing a grpc.aio.Server, registering the servicer, binding the port, and starting. Common case in 5 lines; caller awaits `server.wait_for_termination()`. Operators who need custom server config (interceptors, max message sizes, TLS) construct the server themselves and call `add_InferenceServiceServicer_to_server` directly. **`grpcio>=1.62`** is the first gRPC dep added to kanz-py. Matches the Go side's `google.golang.org/grpc v1.69.0` from PRED-07. **DEFAULT_MAX_IN_FLIGHT = 32**: conservative for a single Python worker on a typical container size. Production tunes per deployment from p99-latency × target-QPS — too low = false positives (rejecting requests the server could handle); too high = backpressure on the actual scoring path (model GPU OOMs, host CPU saturates). Better to start low and raise after observation than the reverse. **PRED-04 + PRED-08 are now symmetric Python halves**: streaming and interactive paths both honour the Model protocol (one model artifact serves both), both honour PRED-02 §1 never-black-hole (DEGRADED on failure, not exception out), both reuse the same degraded-reason identifiers (lifted to module constants), both run in process-isolated worker processes. The two ends of the bus + gRPC hybrid architecture from KANZ_BRAIN

- Go sync inference client (PRED-07): the Go-side gRPC client for PRED-06's InferenceService. **Three resilience primitives bundled in one file** (sync_client.go): SyncClient (gRPC stub wrapper), CircuitBreaker (consecutive-failure breaker with half-open probe), PredictionCache (per-subject_id last-known NORMAL prediction). Co-located because they're the unified resilience layer — splitting them across three files would suggest they're independent concerns, but in practice every call traverses all three (breaker check → stub call → cache record on success / fallback through cache on failure). **PredictionCache is a SEPARATE instance from PRED-04's Python LastKnownCache** even though they share shape. Reason: Go orchestrator process and Python worker process are physically separate — no shared memory dict. Both reset on process restart, both seed from successful NORMAL responses on their own path. A future task could front them with a shared store (Redis, memcached), but for now per-process locality is fine: replay determinism doesn't require cache parity across processes, and the cache is a freshness optimization not a correctness primitive. **`Predict` ALWAYS returns non-nil envelope** — the PRED-02 §1 "never black-hole" rule applied at the Go boundary. Returns `(*PredictionEnvelope, error)` where envelope is always populated; error is non-nil only for OBSERVABLE FAULTS (transport, validation). Caller can ignore error and just branch on `env.Mode` — that's the unified-response semantic from PRED-06. The error is for observability (log/metric), not for control flow. **Custom CircuitBreaker (~50 lines) over a library** (sony/gobreaker, hashicorp/go-resiliency): zero deps, fits PRED-07's scope. No rolling windows, no success-ratio thresholds, no probability-based half-open — promote to a real library if those features become needed. The simple consecutive-failure-count + cooldown model covers the headline case (inference layer is down → fail fast and stop hammering it). **State() method** ("closed"/"open"/"half_open") for tests + future observability dashboards. **Half-open probe semantics**: after cooldown, one call is allowed through. Success → close the breaker. Failure → keep open AND reset openedAt so the next probe waits another full cooldown. Alternative semantics ("probabilistic admission past cooldown") add complexity without changing the headline behavior at PRED-07's scope. **Cache rejects DEGRADED responses** — same trust-laundering protection from PRED-02 §1. Production tunes per deployment. **`NewSyncClientWithStub` for test injection**: clients without `grpc.NewClient` (no real connection). Same dependency-inversion pattern as the Go bus client's `bus.Subscriber` interface for testability. **grpc.NewClient over grpc.Dial**: the newer (non-deprecated) gRPC API. **Plaintext transport via `insecure.NewCredentials()` for now**: production would layer TLS at the gRPC layer — out of PRED-07's scope, can be added as a constructor option later

- gRPC inference service (PRED-06): the SYNC interactive-path RPC definition. Single RPC: `Predict(FeatureVector) → PredictionEnvelope`. **No wrapper request/response messages is the load-bearing decision** — uses PRED-01's existing payloads directly. This locks in the "same proto on both paths" property from PRED-01: a FeatureVector logged from the streaming bus can be replayed into this RPC without field migration; a PredictionEnvelope captured from either path is consumable by the same downstream code. Replay-determinism (EVT-21d-style) extends across transports — a consumer can replay yesterday's streaming features through today's sync endpoint and compare answers. Wrappers would have forced a translation step at each path boundary, breaking the replay symmetry; their forward-compat benefit (add fields without changing RPC signature) is already provided by proto3 message evolution on FeatureVector itself. **Deadline-as-degraded contract**: callers MUST set a gRPC deadline; exceeding it returns a DEGRADED PredictionEnvelope with `degraded_reason = "inference_timeout"`, NOT a gRPC DEADLINE_EXCEEDED status. This applies the PRED-02 §1 "never black-hole" rule to the sync path — returning an error would force callers to handle two failure paths (gRPC status branch + degraded envelope branch). Unified-response shape across both paths means the application code branches on PredictionEnvelope.mode regardless of which transport it's using; the framework concerns (timeouts, retries) don't leak into application logic. **OK/non-OK split has clear semantics**: `OK + DEGRADED envelope` = inference layer reached + decided it couldn't serve full-trust (caller branches on mode); `non-OK gRPC status` = TRANSPORT failure (UNAVAILABLE/INTERNAL/RESOURCE_EXHAUSTED — inference layer unreachable, caller never saw the model's opinion). PRED-07's client library translates non-OK to a synthesized DEGRADED envelope with `degraded_reason = "inference_unavailable"`, so application code sees one shape regardless. The split exists for observability + retry purposes (transport failures retry on different SLOs than application failures) but doesn't leak into the application contract. **Target latency p99 < 50ms** (KANZ_BRAIN) — PRED-07's circuit breaker fails over to the streaming-path cache when this budget is exceeded; the cache is the same `LastKnownCache` shape PRED-04 uses, so the two paths share fallback infrastructure too. **What PRED-06 does NOT define**: streaming RPCs (server-streaming, bidi), batch inference, model-pinning request fields, gRPC health endpoint. Each would be a separate task — and the standard `grpc.health.v1` health protocol is reused for health-checks rather than redefined here. **CODEOWNERS already in place** (`/proto/inference/` → `@kanz-eng/quant-ml`); buf.yaml auto-discovers under `proto/`; no infra changes needed for the addition

With PRED-05 shipped, the loop closes: Go publishes feature events → Python worker drains them → Python worker invokes Model.predict → Python publisher emits predictions → Go consumer can read them. **Class naming resolves a real collision**: the streaming worker type-hints its publisher parameter as `PredictionPublisher` (Protocol); this file ships the implementation. - Inference degraded-mode contract (PRED-02): the prescriptive doc that pairs with PRED-01's `PredictionMode` enum + `degraded_reason` field. **The core rule (§1) is load-bearing**: the prediction layer NEVER returns "no prediction" — always a `PredictionEnvelope` with honest `mode`. Black-holing breaks correctness because the caller can't distinguish "the model is silent" from "the model said no" and has no signal to take the explicit fallback branch. This is the prediction-layer analog of the bus's "poison events go to DLQ, never silently dropped" discipline (event-class-rules §4): make failures visible and machine-actionable, not invisible. **Three degraded triggers, each with a stable machine-readable `degraded_reason` identifier**: (1) inference unavailable — model server down, bus consumer-lag exceeded, gRPC circuit open; (2) inference slow — sync timeout fell through to cache; (3) low confidence — below the per-model threshold (NOT a global constant — set in the model artifact metadata by the model's own contract; a high-conviction signal model picks 0.8, a probability-of-default model picks 0.3). Stable identifiers matter because downstream alerts match on them — free-form text would force every alert to grep, and a wording change would silently break alerts. **The cold-cache case is explicit**: if cache lookup misses (cold start, first-ever subject), the layer returns `value=0`, `confidence=0`, `degraded_reason=no_cached_prediction`. Consumer treats as "no information, do not act." Better than returning the previous subject's prediction or erroring out. **"Unknown confidence" registers as "no confidence"**: a model without calibrated confidence is ALWAYS DEGRADED. Mapping uncalibrated-confidence-to-0 is the only safe default — silently treating it as high-confidence would let untrustable models look trustable. **Producer obligations include both the envelope `quality_flags = QUALITY_FLAG_DEGRADED` and an `observation.v1.DecisionLog` audit entry** on every degraded response. The flag is for payload-blind observability tooling (data integrity layer DATA-02..09 reads `quality_flags` without parsing the payload); the DecisionLog is for human audit independent of whether the consumer logged. Both, not either. **`mode` is per-response, not per-subject**: rules out the anti-pattern of caching "this subject is degraded" — a model just rolled back may serve some subjects from cache (still trustworthy from the previous version) and others degraded (no cache for newly-active subjects). Consumers must not assume subject-level mode stability. **Cross-path uniformity is structural**: streaming and sync paths share ONE decision function — PRED-04 (cache + fallback) and PRED-07 (timeout + circuit) reference the same trigger logic. Divergence would let a consumer route around degraded mode by switching transport, defeating the contract. The implementation enforces this by having one Decider type both paths call. **Consumers treat UNSPECIFIED as DEGRADED** (defensive): a producer that fails to set `mode` is broken, but the consumer should not silently treat the response as full-trust — that would mask the bug. Same defensive-default discipline as event-class-rules' "consumers MUST treat an unknown enum value as UNSPECIFIED" rule. **Explicitly scoped OUT of this doc**: timeout values (per-deployment tuning, not contract), feature-staleness (DATA-02/03's territory — the prediction layer reads but does not redefine), model-version pinning + shadow policy (PRED-09/10 concerns), and the risk engine's `RISK-11` degraded mode (independent — risk query can be NORMAL with DEGRADED prediction inputs, and a fresh prediction can land while the risk engine is degraded). Documenting the boundaries prevents future tasks from accidentally pulling unrelated concerns into the contract

- Risk measure correctness tests (RISK-12): 11 property tests on top of RISK-06/07/08's unit tests, asserting mathematical invariants across seeded random portfolios. **Pattern choice — seeded-loop over `testing/quick`**: stdlib quickcheck generates via reflection — works for plain Go types but cannot synthesise `*commonpb.Decimal` proto pointers without a custom Generator on a type we don't own. The seeded-loop gives the same "run the property against 50 inputs" ergonomic without fighting the proto-type-as-input constraint, and deterministic seeds mean a failure at seed=37 reproduces by re-running with the same seed. Trade-off vs property-based libraries (gopter, rapid): no automatic shrinking. For this codebase's size that's acceptable — when a property fails, the offending seed gives a fully-reproducible portfolio. **The placeholder-formula tests are failure-as-documentation**: `VaR99 / Gross = 0.01` and `Delta == NetExposure` are RISK-07's placeholder identities. When a quant replaces the placeholders with calibrated models, these tests INTENTIONALLY break — the breakage IS the signal that the placeholder is no longer in place, and the failure message points at the right line to update. This is a deliberate engineering pattern: assertions that exist to fail when underlying assumptions change, not assertions that must always pass. **Triangle inequality `|Net| ≤ Gross`**: |Σx_i| ≤ Σ|x_i|. A regression that breaks this is almost always an abs-vs-signed mix-up in compute internals; the property catches it across input shapes (signed/unsigned, mixed exponents, single/multi-position) that handcrafted tests miss. **Cauchy-Schwarz `√(Σσ²) ≤ Σ|σ|`**: defends the conservative-vs-textbook semantics of the two RISK-08 propagators from accidental reversal — if the independent (textbook) bound ever exceeds the perfectly-correlated (conservative) bound, the conservative meaning has been broken. **Permutation invariance** catches a class of bugs where iteration order matters: Go's map iteration is already randomized so map-based aggregations are exercised by default, but explicit position-set shuffling pins the property in the test surface so a future refactor that introduces an ordering dependency fails loudly. **Determinism test** catches accidental nondeterminism (a goroutine-spawning compute optimization, a wall-clock-dependent rounding, a map-iteration leak into output ordering) — none of those exist today, but a future optimization might introduce one, and the test makes that visible. **`dValue` helper** converts Decimal → float64 for property comparisons — uncertainty bands and order assertions don't need money-grade precision, and float64 sidesteps writing a Decimal comparator (which would be a separate test infrastructure burden). For exact-money assertions, the existing unit tests in measures_test.go / exposure_test.go assert at the Decimal field level. The two layers complement: properties at the float level, exact arithmetic at the field level. **propertyIters = 50** — empirically enough to catch input-shape-dependent regressions in a few-second CI run while keeping the compute test suite under a couple seconds total. Tune locally for stress-testing a suspected edge
- Risk degraded mode (RISK-11): first .go file at the top-level `kanz/internal/risk/` directory (all prior risk work lived in sub-packages) — establishes `package risk` as the home for cross-cutting concerns that don't belong to any single sub-package. **Two pieces**: `Detector` (staleness assessment, pure function) and `Cache` (last-known ExposureSet/MeasureSet per portfolio). **Why staleness drives mode, not health-checks, is the load-bearing decision**: the risk engine has no exotic dependencies to poll (no external risk service, no model server, no remote feature store). The single operationally-meaningful observable is `now - portfolio.AsOf` — a healthy ingest pipeline keeps it small; ANY stall (broker outage, applier crash, network partition, GC pause on the source service) shows up as growing staleness, regardless of the specific cause. Tying mode to staleness directly makes the signal cheap (no probe traffic), locally diagnosable (operator looks at the same number), and proxy-free (no "I think we're healthy but staleness says otherwise" disagreements). Health-checks would have to enumerate every dependency; staleness covers all of them implicitly. **Two-threshold ladder, not binary**: `FreshnessBudget = 30s` (above → QualityFlagStale on every response, mode stays Normal — caller sees the signal but the engine is still trustworthy); `DegradedThreshold = 5m` (above → ModeDegraded + QualityFlagDegraded + QualityFlagStale — caller decides whether to act, fall back to cache, or refuse). The intermediate STALE state matters because real systems have transient stalls (a 90-second broker hiccup is a normal operational event, not a degraded engine); flipping straight to ModeDegraded would alert-spam. Defaults are conservative starting points; production tunes per deployment. **Zero-AsOf gets ModeDegraded + QualityFlagDegraded regardless of clock**: a portfolio never-yet-applied (cold-start, first-time-seen ID) has no fresh data, even cache fallback would be empty. Returning ModeNormal here would let callers read "no data" as "zero risk" — a much more dangerous default than the explicit degraded signal. **Boundary semantics matter**: staleness EQUAL to threshold is FRESH ("above the budget" not "at the budget") — off-by-one regression caught by an explicit test. The exact semantics are documented in code and test so a future change doesn't silently shift the boundary. **Cache is best-effort, no TTL**: the cached value carries its own AsOf; Detector handles staleness from the AsOf. A TTL on the cache would duplicate the staleness logic and create a second source of truth for "is this still valid". Eviction is overwrite-on-next-store; chronological cache (multiple historical snapshots) is a different feature that some replay tooling might want, but degraded fallback only needs the most recent good value. **Nil-store is no-op** (vs panic or phantom-entry): callers may upstream-protect with nil-checks anyway, but defensive nil-handling here means a regression that passes a nil result through doesn't crash the engine or create a phantom cache entry that masks a real bug. **Integration pattern for the orchestrator** (which doesn't exist yet — separate task): on successful compute, `Cache.StoreX(id, result)`; on compute failure or budget-exceeded, fall back to `Cache.LookupX` + tag via `Detector.Assess(cached.AsOf())`. The api/v1 surface's Engine.Health calls `Detector.Health(latestAsOf)` where latestAsOf comes from the state.Store (max AsOf across portfolios or per-portfolio depending on the orchestrator's policy). **What RISK-11 deliberately does NOT do**: subscribe to events, drive periodic background re-computation, expose configuration via the api/v1 surface — those are orchestrator concerns. RISK-11 is the primitives; the policy lives upstream

- Risk scenario engine (RISK-09): the pure-function what-if evaluator that takes (state, shocks) → projected measures. **The architectural tension that drove the design**: RISK-02's arch test forbids outsiders from importing `kanz/internal/risk/scenario/`, but external callers (orchestrator's HTTP API, scenario tooling) need to CONSTRUCT shocks to drive `Engine.EvaluateScenario`. - Risk uncertainty propagation (RISK-08): three propagation primitives + integration with the RISK-07 baseline measures. **The correlation-assumption split is the load-bearing architectural decision**: different propagation math comes from different correlation assumptions, and the propagation layer can't paper over the choice without silently misleading consumers. Two endpoints + a scalar rule: `PropagateSumIndependent = √(Σσ_i²)` (uncorrelated, standard textbook); `PropagateSumPerfectlyCorrelated = Σ|σ_i|` (conservative when correlations unknown — overestimates rather than underestimates); `PropagateScalar = |c|×|σ|` (exact, no assumption — covers constant-scaled measures like VaR99 = 0.01×Gross). The measure function picks which rule applies per measure; the default for cross-position aggregates is **independent** because that's the standard textbook propagation and matches the "no correlation data yet" engine state. A future iteration can offer per-measure mode selection or a correlation matrix without changing the primitives. **nil semantics is the second load-bearing decision**: per-input nil ⇒ skip (compatible with the "MarketValueUncertainty nil = no uncertainty for this position" convention); **all-nil ⇒ return nil, not zero**, so the api/v1 `Measure.UncertaintyAbs = nil` "no uncertainty propagated" signal stays meaningful. Returning Decimal{0} would falsely claim a calibrated zero confidence interval, which is a much more dangerous signal than "we don't know" — a downstream that treats the zero as gospel could underestimate risk while looking properly hedged. **`decimalSqrt` via float64 round-trip is a deliberate precision trade-off**: confidence intervals don't need the same precision as money values, float64's 15-significant-digit precision is more than sufficient for ~6-decimal uncertainty reporting, and writing a pure-integer sqrt would add code without observable benefit. Fixed output exponent (`uncertaintyExp = -6`) prevents propagation chains (sqrt-then-sum-then-sqrt) from drifting toward extreme exponents; negative input (which would happen only if upstream variance arithmetic underflowed) clamps to zero, recovering to "no uncertainty" rather than producing NaN that would propagate through every downstream measure. The upgrade path to `math/big.Rat` end-to-end is documented as the "if it matters" lever — flagged alongside `pow10`/`mulDecimal` overflow risks. **Domain field added: `Position.MarketValueUncertainty *commonpb.Money`** — the per-position uncertainty input the propagation reads. The wire proto (`domain.v1.PositionState`) does not yet carry a matching field, so RISK-04/05 leaves it nil and real engine output has UncertaintyAbs nil today. The propagation paths shipped are exercised by tests until either (a) the wire schema gains an `uncertainty` field or (b) RISK-11's degraded-mode synthesizes uncertainty from staleness. Both upgrade paths leave RISK-08's primitives unchanged. **Why a domain-only field, not a wire-schema field**: the schema is the constitution; adding a field requires CODEOWNERS review and `buf breaking` validation. Until a producer can populate the value meaningfully, adding the field is premature — and the domain field gives RISK-08 a place to land the propagation algorithm + tests without blocking on the schema gate. **Currency rule preserved**: uncertainty inputs are skipped if their currency doesn't match the portfolio's BaseCurrency, same no-FX-in-compute discipline as RISK-06/07. Mixing uncertainties across currencies without FX conversion would be arithmetically meaningless. **Integration with the four baseline measures**: GrossExposure/NetExposure/Delta share `sumUncertaintyInBaseCurrency` (independent sum); VaR99 uses `PropagateScalar(var1pctOfGross, σ_gross)`. The same MeasureFunc signature works — RISK-08 just populates the previously-nil `UncertaintyAbs` field; no api/v1 change needed, no test churn on RISK-07's tests

- Risk exposure computation (RISK-06): first compute layer + first decimal-arithmetic helpers in `kanz/internal/risk/compute/`. **Two-dimension emission today**, both derivable from existing Position fields: `ExposureByInstrument` (canonical — one Exposure per marked position) and `ExposureByCurrency` (aggregated by `MarketValue.CurrencyCode`). **ExposureBySector is in the closed `domain.ExposureDimension` enum but deferred** because deriving it needs an instrument→sector reference table the engine does not yet own (this would be a market/reference-data dependency the risk module doesn't have today). A RISK-06b can inject a `sectorLookup func(InstrumentID) string` without changing the existing `ComputeExposure` signature — the parameter would just be added; current callers continue to get instrument + currency only. **No cross-currency conversion in compute**: bucketing on currency first makes each per-bucket sum well-defined without FX; cross-currency aggregation needs an FX-conversion layer that lives outside the risk module (likely a market-data service consumed via the bus). This is a deliberate scope cut — the rate-of-change of FX rates is its own problem and conflating it with exposure compute would couple this layer's correctness to a moving target. **Skip semantics for missing data**: positions with nil MarketValue are skipped (no mark yet ⇒ no expressible exposure — the alternative of estimating from Quantity × AveragePrice would mislabel stale data as fresh); zero-quantity positions (RISK-05 retains them for audit lineage) flow through producing zero-row exposures — the position's continued existence is information the query response carries. **Decimal helpers in compute/decimal.go**: `addDecimal` aligns to the more-precise exponent (1.50 + 0.025 → 1525×10^-3 not 1.525 lossy); nil-as-zero convention for accumulator initialization; `addMoney` requires matching currency (caller asserts via bucketing); `pow10` is unguarded — bounded by typical financial-data exponent differences. **If RISK-07's VaR hits extreme scales** (e.g. notional × tail-quantile × time-window) the helpers should switch to `math/big.Int` for coefficient or `math/big.Rat` end-to-end — flagged as the "if it matters" upgrade path so the simpler implementation ships first. **Why decimal helpers live in compute, not domain**: decimal arithmetic is a computational concern, not a domain entity. Putting them in domain would bloat the domain package and create a cross-package import pattern (compute imports domain imports common.v1 arithmetic) that's harder to reason about than the current compute-owns-its-math layout. **AsOf propagation through ExposureSet**: the api/v1 surface returns AsOf via `v1.ExposureSet.AsOf()` so callers see freshness; ComputeExposure pulls it from the Portfolio (whose AsOf is the latest state-apply timestamp from RISK-05). Stale state → stale exposure — the engine doesn't pretend, doesn't extrapolate
- Risk state apply (RISK-05): the heart of the engine — implements `ingest.Applier`, owns the in-memory state, enforces per-aggregate ordering and idempotency. **Three lazy-created maps keyed by PortfolioID**: portfolios (`*domain.Portfolio`), locks (per-portfolio `*sync.Mutex`), dedup (per-portfolio bounded sliding window). The wrapping `Store.mu` is held briefly only for lookup-or-create; per-portfolio locks then serialize the actual apply. Two-level locking trades a small acquisition cost for parallel applies across portfolios + serialized applies within each. **Per-aggregate ordering primitive is the load-bearing decision**: a `sync.Mutex` per portfolio is the cheapest primitive that gives cross-event-type serialization. The bus guarantees per-partition ordering only (event-class-rules §1), but a portfolio receives PortfolioState on one partition and PositionState (potentially many instrument-keyed partitions) on others — per-aggregate ordering across all of them is THE engine correctness invariant. Alternatives considered: per-aggregate goroutine + channel (adds shutdown complexity, no contract benefit); sharded mutex pool (avoids unbounded map growth but defeats per-aggregate isolation). Mutex-per-portfolio wins on simplicity. **Per-aggregate dedup window** is defense-in-depth alongside the bus.Consumer's global window (EVT-17d): 2m TTL / 10k entries match the bus defaults so the two layers reinforce — a duplicate within window is caught by either. Per-aggregate scoping (rather than global) catches the cases bus dedup misses: multiple bus.Consumers feeding the same Applier (the typical orchestrator wiring — one Consumer per state subject), and process restarts that drop the bus dedup window but leave committed state intact. Matches event-class-rules §1 "dedup against a bounded window sized to the broker's redelivery window" without conflating keys across aggregates. **Check-then-Record pattern (not atomic check-and-set)**: `Seen` reads the window, `Record` writes after successful apply. A transient apply failure must remain retryable, which means recording only after the apply succeeds — same discipline as bus.Consumer's dedup loop. Two concurrent deliveries of the same key can both pass `Seen` before either `Record`s, so the underlying Applier must be idempotent at the data layer (which `SetPosition` is — same instrument id overwrites). **Snapshot semantics**: latest-wins-by-event-time (event-class-rules §3). Hard reset — `ClearPositions` then apply snapshot positions then `SetAggregate` then `SetSnapshot(LogPosition)`. Stale snapshots (snapshot.AsOf < portfolio.AsOf) are silently skipped AND dedup-recorded (a real envelope we've decided not to apply; recording prevents redelivery wasting cycles). **Lazy portfolio creation with empty BaseCurrency**: bus does not guarantee cross-event-type ordering, so PositionState may arrive before PortfolioState. Lazy-create lets the engine accumulate positions until the first PortfolioState/PortfolioSnapshot fills BaseCurrency. The alternative (reject events for unknown portfolios) rejects many valid sequences during rolling deployments and bootstrap — a worse default. **`Lookup` returns live pointer, not clone**: internal contract for compute layers (RISK-06/07) which read while holding appropriate locks or before passing across goroutine boundaries; the api/v1 surface clones before returning to external callers. Cloning every Lookup would multiply read cost by aggregate size for the typical query-heavy workload. **`toDomainPosition` lives in state (not domain) package**: keeps the domain package free of `kanz-schemas/domain/v1` imports — only `common/v1` leaks through Position's field types. RISK-05 is the single proto→domain translation site; RISK-10 will be the single domain→proto translation site for the publish path. **Domain extension landed in this task**: Portfolio gained `displayName`/`cashBalance`/`totalMarketValue`/`positionCount` getters + `SetAggregate(AggregateUpdate)` bulk setter + `ClearPositions` snapshot-reset hook. Position gained `MarketValue`/`RealizedPnL`/`UnrealizedPnL` public fields + a bug fix on `AveragePrice` (was `Money`, proto says `Decimal`). `AggregateUpdate` value-type carries the proto→domain values without coupling the domain package to `domain.v1`. **`tsTime` nil-safety**: uses concrete `*timestamppb.Timestamp` parameter (not an `AsTime() time.Time` interface) — calling `AsTime()` on a typed-nil pointer returns Unix epoch (1970), not Go's zero time, which would falsely look like "state applied" to AsOf checks. This is a classic Go interface-nil-vs-typed-nil trap; using the concrete type avoids it
- Risk state ingestion (RISK-04): the bus→engine bridge. **Single-responsibility design**: Ingestor.Handler is a `bus.EventHandler` that takes (envelope + payload bytes — already validated by bus.Consumer per EVT-17), switches on `env.EventType`, unmarshals into the right `domain.v1` proto, and dispatches to an `Applier` interface. Three event_types routed: `risk.portfolio.revalued` (PortfolioState), `risk.position.changed` (PositionState), `risk.portfolio.snapshot` (PortfolioSnapshot, STATE_SNAPSHOT class). Event type names follow kanz-schemas/docs/subject-taxonomy.md §1 (`{domain}.{entity}.{event_type}`, past-tense for FACTs) and the per-payload doc comments in portfolio.proto ("payload of portfolio-revalued FACTs" / "payload of position-changed FACTs"). **Scope-split with RISK-05 is load-bearing**: Ingestor does *pure routing* — no translation, no idempotency, no ordering. Those belong to RISK-05 because they need per-aggregate state and the per-aggregate lock the Applier owns; splitting them across two packages would make the per-aggregate guarantee impossible to enforce. The split also gives RISK-04 a one-page implementation with zero state — easy to reason about, easy to test. **Applier takes proto directly, not pre-translated domain types**: the Applier needs both envelope metadata (for dedup keying on idempotency_key, ordering on partition_key + producer_sequence, as_of from envelope.event_time) and the typed payload — translating to domain types in ingest would force Applier to receive both, doubling the boundary surface. Letting RISK-05 own the proto→domain mapping keeps the boundary at one type per method. **Applier interface declared in ingest, not state**: RISK-04 lands before RISK-05 by design — the interface is declared here so tests + the orchestrator can wire a fakeApplier today and RISK-05 just needs to satisfy it tomorrow. This is the same "lands-before-impl" ordering RISK-02's arch test followed. **Live-only consumer scope**: REPLAYED-flagged events are rejected by bus.Validate before Handler runs (EVT-20c live-sink guard) — a future replay-scoped state consumer would construct a separate Ingestor wired to bus.WithValidator(bus.ValidateReplay), reusing the same Applier interface but with a different Consumer config. **Unknown event_type surfaces as ErrUnknownEventType** (errors.Is-able) → bus retry+DLQ picks it up. Misconfiguration must be loud and operator-visible, never silently dropped; the bus retry+DLQ path (EVT-17e) puts it in front of an operator after MaxAttempts. **Unmarshal errors surface too**: a malformed payload reaching the engine means a publisher emitted bytes that don't match the declared event_type — that's a contract violation worth a DLQ entry, not a swallow. **No subscription wiring in this package**: Ingestor exposes Handler only; the orchestrator calls bus.Consumer.Subscribe per state subject with Handler as the callback. Keeps "which subjects to subscribe to" (orchestrator policy) separate from "how to translate" (ingest concern)
- Risk domain model (RISK-03): the in-memory aggregate types backing the api/v1 opaque interfaces. **Two-layer separation from kanz-schemas proto types is load-bearing**: `domain.v1.PortfolioState` / `PositionState` (kanz-schemas) is the WIRE shape — designed for serialization, schema-evolution, cross-language consumption. `domain.Portfolio` / `domain.Position` (this package) is the engine's WORKING in-memory shape — designed for fast access, immutability of snapshots, natural Go ergonomics (typed `InstrumentID` / `CurrencyCode`, methods on the aggregate). Mapping happens at the boundary: RISK-04 unmarshals proto → constructs domain values; RISK-10 reads domain values → marshals proto for publishing. The cost is a small duplication tax; the win is independent evolution — adding a domain-only field doesn't touch the wire schema, and adding a wire field doesn't force a domain shape change until the engine actually needs it. **Implements api/v1 opaque interfaces** with compile-time assertions (`var _ v1.ExposureSet = (*ExposureSet)(nil)`) — catches any contract drift at build time, cheaper and stricter than a runtime test. The Measure VALUE type lives in api/v1 (`v1.Measure`) because callers read its fields directly; the Measure SET type lives in domain (`domain.MeasureSet`) so RISK-07 can swap representations (map vs flat slice, indexed vs lazy) without churning the api/v1 contract. Same split for ExposureSet (domain) vs there-is-no-v1.Exposure-because-callers-go-through-the-set-interface. **Immutability discipline**: every accessor (Positions, Items, Names) returns a fresh slice/map copy, never the internal storage. RISK-05's state-apply layer is the single writer; one ingest goroutine + many query goroutines is the concurrency model RISK-04 will use, and the read-only accessor surface keeps that contract clear. **Money/sizes/prices use common.v1 types directly** (banned-double rule): Quantity is `*common.v1.Decimal`, AveragePrice + Exposure.Gross/Net are `*common.v1.Money`. No domain-local Decimal/Money wrappers — reuse keeps the api surface coherent with the events RISK-10 publishes and avoids per-read conversion. **Closed ExposureDimension enum for v1** (ExposureByInstrument canonical, ExposureByCurrency, ExposureBySector): new dimensions take next constant; existing values never repurposed — mirrors envelope-policy §4 field-number discipline at the Go-type level. RISK-06's compute layer will derive non-canonical dimensions from per-instrument exposures. **Zero-quantity positions retained for audit lineage**: explicit removal only via `Portfolio.Forget` when a state event retires the instrument — otherwise a closed position is a Position with Quantity=0 and continues to ride through query responses for traceability. **Snapshot bootstrap hook**: `Portfolio.SetSnapshot(asOf, *common.v1.LogPosition)` records the durable-log coordinate from the most recent applied snapshot — RISK-04 reads this on cold start to know where to resume the log per event-class-rules §3 (snapshot then log-resume, no gap, no double-application)
- Import-boundary architecture test (RISK-02): pairs with RISK-01 — RISK-01 declared the api/v1 contract, RISK-02 makes it enforceable. **Why a separate test and not a Go language feature**: Go's `internal/` rule restricts to "rooted at the parent" — for `kanz/internal/risk/X` that means the whole `kanz` module can already import it. The architecture test adds the finer-grained "outsiders use api/v* only" rule the contract design depends on. **Test mechanics**: shells out to `go list -json ./...` from the module root (resolved via `go env GOMOD` → `filepath.Dir`, platform-safe), streams the per-package JSON, walks `Imports + TestImports + XTestImports` for each package. Direct only — transitive imports come from intermediate packages that have their own boundaries to enforce. **Test code is held to the same boundary** (TestImports/XTestImports checked too) because a test-only consumer of an impl package creates a phantom coupling that breaks the moment the impl symbol is renamed — the arch test exists to prevent exactly this slow rot. **Library-choice trade-off**: `go list` over a third-party arch-lint library (go-arch-lint, modgraph, etc.) trades expressiveness for zero deps, regular `go test` integration, and structured JSON output suitable for streaming. The two-rule set (outsiders-use-api-only, api-does-not-import-impl) is small enough that a custom matcher beats DSL overhead. **Two rules, not more**: kept tight to the contract design; resist adding "code style" rules (max-deps, naming conventions) — those belong in linters, not the arch test. **Convention for future modules**: `kanz/test/arch/{module}_boundary_test.go`, reusing the shared `loadPackages` / `moduleRoot` / `allImports` helpers in the same package. PRED and DATA modules will follow the same pattern. **Land-before-impl**: with only api/v1 shipped (RISK-01) and no impl packages yet (RISK-03..11 still BACKLOG), both tests pass trivially today — they become teeth-bared as the impl lands. This is the right ordering: the test ships first so the first violating commit fails CI immediately, instead of trying to retrofit boundaries after the codebase has grown across them
- Risk-engine module interface (RISK-01): first tenant of `kanz/internal/` (greenfield until this task — `kanz/` previously had only `pkg/`, `services/`, `infra/`, `test/`, `tools/`, `ts/`). The layout convention is established now: `kanz/internal/{module}/api/v{N}/` for the external interface, `kanz/internal/{module}/{impl-package}/` for the implementation packages siblings cannot import directly. RISK-02 will wire the import-boundary architecture test that enforces this at build time. **Why a sub-package `api/v1/` rather than `kanz/internal/risk/v1.go` at the module root**: keeps the public surface importable as a single package without consumers pulling in every implementation file's transitive deps, and the versioning subpath (`v1` → `v2`) mirrors the kanz-schemas package convention (envelope/v1, market/v1, ...) so the mental model is the same across schema and Go-module versioning. **Versioning discipline**: api/v1 is additive-only within v1 — the same logic as envelope-policy §1 (a method removed or retyped breaks every caller, breaking is a one-way door requiring `v2/` + dual-path migration). A new method joins Engine only when every plausible implementation can supply a non-degraded answer; otherwise it belongs on a separate interface. **Engine surface is query + scenario + health only**: 4 methods — `Exposure`, `Measures`, `EvaluateScenario`, `Health`. NO Apply / Mutate / Command, per the anti-decision "all state changes must be event-driven" — RISK-04 ingests state via FACT events, RISK-10 publishes risk outputs as FACT events; the api/v1 surface is read-side + pure-function scenarios only. Callers needing notifications subscribe to the bus directly, not through this interface. **Rich-type strategy**: `ExposureSet`, `MeasureSet`, `ScenarioShock` are minimal-method interfaces (e.g. `ExposureSet.AsOf()`, `MeasureSet.Lookup(name)`) — RISK-03 provides the concrete domain types, but api/v1 leaves the shape under tiny interfaces so the domain package can evolve fields freely without churning every api/v1 caller. This is the textbook "API DTOs vs domain entities" split, applied at the interface layer rather than the struct layer. **`Measure.Value` uses `*common.v1.Decimal` directly** — the risk module already depends transitively on the schemas SDK via event ingestion / publishing, so reusing the canonical exact-decimal type from `kanz-schemas/proto/common/v1/decimal.proto` (mandatory per the BRAIN "double is banned for prices/sizes/money" rule) keeps the API surface coherent with the events RISK-10 publishes and avoids per-read string→decimal parsing at every call site. **api-local QualityFlag enum** (`QualityFlagDegraded`, `QualityFlagStale`) rather than the envelope's proto QualityFlag — keeps api/v1 free of envelope-versioning churn for purely Go-API concerns; the api enum mirrors the envelope semantics for the two cases that matter at the query layer (degraded, stale) without coupling. **Degraded mode surfaced two ways**: explicit `Mode` field on `Health()` returns + per-response `QualityFlags` slice on every query response — callers cannot accidentally consume degraded data without seeing the signal at the point of use. **Sentinel errors**: `ErrPortfolioNotFound` (portfolio unknown — may exist in source-of-truth log but no state event ingested yet) and `ErrInvalidRequest` (api-contract violation — empty PortfolioID etc., distinct from transport/runtime errors so callers branch correctly)
- Replay determinism contract (EVT-21d): schema-evolution.md §8 promises "replaying an old log with current code must produce identical output, which is only true if every intervening change was genuinely non-breaking or genuinely a new vN" — EVT-21d is the runtime proof. This is the **forcing function** for two production-critical invariants: (1) Pipeline's marshal step must be wire-stable across runs (any future nondeterminism — per-run metadata stamping, map-field reordering, generator regression — surfaces here as a failing test before it corrupts a production replay); (2) `StampReplayed`'s idempotency must hold at the wire level (chained re-runs converge to byte-stable output). **Tests live at `kanz/test/contract/replay/`** alongside the other EVT-21 contract trees. Package `replay_test` (external) so they exercise only `tools/replay` + `pkg/bus` public surface. **Four assertion axes**: (a) **same log + same RunID → byte-identical** (the headline claim); (b) **same log + different RunIDs → identical body, only subject differs** (proves RunID-orthogonality — RunID is the only run-scoped input to wire bytes; rules out hidden coupling); (c) **replay-of-replay convergence** (re-feed Run1 output as Run2 input, same RunID — chained outputs must converge because `IsReplayed` short-circuits `StampReplayed`'s mutation, so no field drifts); (d) **envelope identity preservation** (clone every source envelope pre-run via `proto.Clone`, assert every identity field — `EventId`, `IdempotencyKey`, `ProducerSequence`, `CorrelationId`, `CausationId`, `Source`, `ProducerVersion` — survives Pipeline byte-equal to the cloned original; only `QualityFlags` permitted to grow by exactly one `REPLAYED`). **The §8 compat-during-replay link is asserted directly**: simulate a future publisher's event in an old log by appending an unknown varint field at tag 1000 to envelope wire bytes (the same `protowire.AppendTag` technique EVT-21c uses), unmarshal so the unknown bytes land in `ProtoReflect().GetUnknown()`, replay through Pipeline, Unframe output, assert the unknown field is preserved. This is the proof that Pipeline's `proto.Marshal(&EventFrame{Envelope, Payload})` correctly surfaces the proto3 unknown-fields machinery — without that, the §8 claim is hollow. **fakeSource + capturePub external-package mirrors**: rather than re-export the existing internal helpers in `tools/replay/run_test.go`, mirror them inline so the contract test is self-contained and decoupled from internal test infrastructure (which can refactor without breaking the contract suite). **canonicalLog rebuilds per call** because Pipeline mutates `Envelope.QualityFlags` in place — two runs sharing slice-backing arrays would falsely converge by mutating shared state, not by genuine determinism. **What EVT-21d does NOT cover**: cross-broker replay (Kafka↔NATS reconciliation belongs to DATA-05), partial-replay resumption (operator-tool concern, not a contract), and per-payload-schema replay (each domain's contract tests own that). **EVT-21 epic complete**: 21a (receive-side rejection), 21b (cross-language wire parity), 21c (forward + backward compat), 21d (replay determinism). Together they bracket the envelope contract across four orthogonal axes — receive, language, time-direction, and replay-stability — so a regression in any one of them fails the contract suite before it can corrupt a production deployment
- Schema compatibility contract (EVT-21c): the envelope-policy + schema-evolution docs **promise** that proto3's unknown-field preservation + wire-zero-omission semantics give us free forward + backward compatibility across the envelope and every payload schema. Two existing gates check the schema *text* but not the *runtime* — `buf breaking` (EVT-07) catches wire-breaking schema edits at PR time; CODEOWNERS review catches the semantic breaks `buf breaking` cannot see (schema-evolution §5). Neither proves the bindings actually behave correctly at runtime — a generator regression that drops unknown fields, or a binding that fails on a missing optional, would silently corrupt replay and rolling deployments. **EVT-21c is the third leg**: a runtime contract test that asserts wire-runtime behavior matches the docs' promise. **Tests live at `kanz/test/contract/compatibility/`** alongside the other EVT-21 contract trees (envelope/, serialization/, replay/). **Forward-compat technique**: use `google.golang.org/protobuf/encoding/protowire` (raw wire-format helpers) to *append* an unknown varint field at a high tag number (1000 — well above the 1–19 currently allocated for Envelope, outside the 19000–19999 reserved range), unmarshal via current bindings, inspect via `m.ProtoReflect().GetUnknown()` to confirm the tag is preserved, re-marshal, scan with `protowire.ConsumeField` to confirm the tag survives the round-trip. This is the canonical "old code, new bytes" simulation without needing a synthetic parallel proto package. **Backward-compat technique**: proto3 wire-omits zero-valued scalars, so an envelope with optional fields unset produces *identical wire bytes* to a v0 producer that never had those fields. Asserted by round-trip (optional fields default to zero) AND by a stronger wire-byte equality check (explicit-zero envelope marshals identically to unset envelope under `Deterministic: true`). **EventFrame-layer caveat**: the forward-compat property holds for `bus.Unframe` ("doesn't reject"), but EventFrame-level unknown fields do NOT survive a replay re-publish because EVT-20's Pipeline re-marshals from `Envelope + payload`, not from raw frame bytes — the test name + comment call this out explicitly so a future reader doesn't assume preservation across replay. **Payload opacity asserted explicitly**: EventFrame.payload round-trips identically for nil/empty/ASCII/high-bit/large-blob/parseable-Timestamp/Timestamp-with-unknown-field — proves the payload-blind tooling promise holds. **Payload-schema compat demonstrated via `timestamppb.Timestamp` as stand-in**: rather than generate a synthetic v1+v2 proto package, use `Timestamp` (real bindings, known fields 1+2) and simulate a future v2 by appending field 99 via raw wire bytes. Two assertions: v2 bytes → v1 decoder preserves unknown field; v0 bytes (only `seconds` set) → current decoder reads `nanos=0`. The pattern generalizes to any payload schema; the test is the existence proof. **What 21c is NOT**: it does not enumerate every Envelope field's compatibility properties (the validator and unit tests already do that), and it does not assert per-payload schemas (each domain owns its own compat tests in its `proto/{domain}/v1/` subtree — this layer is the universal proof). **Three-way bracketing**: 21a (consumer rejects bad bytes), 21b (cross-language reads same bytes identically), 21c (current code reads past + future bytes safely). Together they cover the envelope contract from receive-side, language-side, and time-side
- Cross-language serialization parity (EVT-21b): the contract claim — "Go bytes can be read by Python and TS with identical envelope semantics" — needs **one canonical source of wire bytes** that all three languages assert against. Two designs were considered: (a) each language marshals its own envelope and asserts the bytes match the others (symmetric); (b) one language generates **golden fixtures**, the others load and assert (asymmetric). **(b) won** because (a) only catches mutual divergence, not divergence from a third-party publisher — and the wire bytes from a future Java/Rust client are exactly what (b) simulates (a fixed binary input the language under test must handle). It also makes the "did the proto bindings drift?" check trivially testable: when `envelope.proto` changes, the Go generator's output changes, the on-disk fixtures drift, and the drift-guard test fails with the exact regen command. **Go is the canonical generator** (not a language-neutral YAML) because the Envelope is the constitution and the Go bus client is the reference implementation — building fixtures *from Go envelopes* keeps the contract tracking the live `envelope.proto`. **Layout**: `kanz/test/contract/serialization/fixtures.go` (the catalog, exported), `cmd/genfixtures/main.go` (CLI that writes `.bin` + `manifest.json`), `parity_test.go` (in-memory parity + on-disk drift guard), `fixtures/` (generator output — committed for reproducibility, regenerated via the CLI). **Manifest design**: JSON, snake_case (proto canonical names), enums as string names so a language can resolve via its enum-by-name API, timestamps split into `{seconds, nanos}` matching `google.protobuf.Timestamp`'s wire shape so no language needs an RFC-3339 parser. **Fixture set** covers every event class plus the corner cases that have historically failed cross-language round-trips in other systems: zero-valued `producer_sequence` with empty `partition_key` (validator enforces this explicitly), lineage-populated envelopes (correlation/causation/trace), repeated-enum encoding (`QualityFlag_QUALITY_FLAG_LATE` — deliberately not REPLAYED because the validator special-cases that one), and COMMAND with caller-set `idempotency_key != event_id`. **Deterministic marshal**: `proto.MarshalOptions{Deterministic: true}` ensures the wire bytes are byte-stable across regenerations — Envelope has no maps so the practical risk is small, but it's the right defensive default for a golden-fixture suite. **Skip-with-hint pattern**: Python/TS tests check `manifest.json` exists and skip with the exact `go run ./cmd/genfixtures …` command if absent — so a dev who hasn't regenerated yet doesn't see opaque "file not found" but the actionable next step. CI runs the generator before all three test suites. **EVT-21a vs 21b distinction**: 21a's tests (`kanz/test/contract/envelope/`) are language-internal — they assert the Go consumer rejects bad wire bytes. 21b's tests are cross-language — they assert all three languages read the same bytes into the same envelope. Together they bracket the envelope contract from both sides
- Envelope contract tests (EVT-21a): contract tests live in `kanz/test/contract/{topic}/` — one subdir per EVT-21 subtask (`envelope/` for 21a, `serialization/` for 21b, `compatibility/` for 21c, `replay/` for 21d). Distinct from the unit tests in `kanz/pkg/bus` in two load-bearing ways: (1) **placement** — `kanz/test/...` sits above the bus package, package name `envelope_test` so tests can only touch the public surface (Producer, Validate, ValidateReplay, Unframe); (2) **intent** — these are the wire-level **spec** that EVT-21b will mirror across Python + TS round-trips and EVT-21d will reuse for replay determinism. The hand-framing pattern is the key technique: build a bad `Envelope`, marshal as `EventFrame`, `Unframe` then `Validate` — this asserts the **consumer-side** rejection holds for any wire bytes (including those a buggy or future-language publisher might emit), not just envelopes that the Go `Producer` would refuse to stamp. The `Producer` enforcement (publish-side) and `Validate` enforcement (receive-side) are defense-in-depth; the contract tests prove the receive-side half independently. Test layout choices: shares `captureClient` + `validEnvelope` patterns with the bus unit tests (same Producer wiring), but lives in `envelope_test` package so it consumes the bus only through exported API; one test function per assertion (no super-tables) so failure messages point at the violated invariant by name; per-class invariant test branches on EventClass so adding a new class only adds one case rather than duplicating the whole test. **Why these are not redundant with `bus/validate_test.go`**: the unit tests prove `Validate(hand-constructed envelope)` does what its godoc says. The contract tests prove `Validate(Unframe(Marshal(EventFrame{env, payload})))` — i.e., the full wire round-trip — produces the same outcome, and that the `Producer.Publish` → wire path lands an envelope that passes that same validator. They are the boundary tests; the unit tests are the implementation tests

- Postgres StateStore impl (PERS-01b): `postgres.go` over the EVT-16a pgxpool pattern (caller owns the pool). **Per-aggregate row locking falls out of the upsert, not an explicit `SELECT … FOR UPDATE`**: `INSERT INTO portfolios … ON CONFLICT (portfolio_id) DO UPDATE` takes a row-level lock on that portfolio's row for the tx, so two concurrent Saves for the same portfolio serialize (the second blocks at the conflicting upsert) — the durable mirror of RISK-05's in-memory per-portfolio mutex; different portfolios never contend. **Read-committed (pool default) is deliberate**, NOT the registry's Serializable: the row lock already gives per-aggregate ordering and there is no cross-aggregate invariant to protect (the registry needed Serializable only to assign version=latest+1 atomically). **Save is full-replace within one tx**: upsert the portfolio row, then `DELETE … WHERE portfolio_id` + re-insert positions and applied_keys — matches snapshot hard-reset (a position dropped from the record is removed) and keeps the durable applied-key set the same bounded-tail shape as the in-memory dedup window. **Money/Decimal ↔ BYTEA via `proto.Marshal`** with a `reflect.IsNil` guard in `encode` (the typed-nil-in-interface trap: a nil `*commonpb.Money` passed as `proto.Message` is a non-nil interface over a nil pointer, so `m == nil` is false); nil message ⇒ nil bytes ⇒ SQL NULL. **LogPosition decomposed into `log_{topic,partition,offset}` columns** (topic presence is the set/unset discriminator), uint32/uint64 stored as BIGINT — fine for real Kafka coordinates. **Zero `time.Time` ↔ SQL NULL** (`nullTime`/`derefTime`) so "no state applied yet" round-trips as NULL, not the proto Unix epoch (the same zero-vs-epoch hazard `state.tsTime` guards on the apply side). **LoadAll is 3 table scans grouped in memory** (portfolios + positions + applied_keys, joined by portfolio_id) rather than N+1 per-portfolio reads — it's the bootstrap read (PERS-01d).
