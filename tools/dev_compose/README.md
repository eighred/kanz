# Disposable developer Compose qualification

The [workflow](../../.github/workflows/dev-compose.yml) runs the existing developer Make recipes on a fresh Ubuntu KVM guest. The repository's short-lived package reader acquires the two GHCR mirror images on the runner. The guest receives OCI content, its own source archive and the pinned Buf binary. No registry credentials or Docker socket are forwarded. The reader validates the published index, linux/amd64 manifest, config and every layer against the [input pins](images.json). The distroless pin is the [organization mirror's observed input](https://github.com/eighred/kanz/actions/runs/43884493421/job/133358844416).

The unprivileged generation account initially reaches only a loopback proxy for the public Go and Buf inputs. It runs the original bootstrap and complete Go, Python and TypeScript SDK generation. The [order-only prerequisite](phase.mk) adds a pause after generation to the same GNU Make invocation. The acquisition phase verifies Go modules and warms the common dependency layer from the three actual Dockerfiles. The runner removes the guest's single network card. The host then checks that the guest has only its own root disk and the guest confirms it has no IPv4 or IPv6 default route. Only then does the generator receive access to the guest's Docker socket and the normal `make up` recipe continue. The service compiler and runtime have no external network route. The registry pins and acquisition script identities are reviewed together when their upstream inputs change.

The remaining checks exercise restricted-role PostgreSQL RLS, both Kafka listeners, the canonical JetStream inventory and the authenticated four-instrument PF1 read. The run records resource identities, the volume directory inodes and the persisted portfolio checkpoint before shutdown, then restarts without reseeding. The explicit Make reset and VM deletion have separate absence checks. The fixture uses the public local development identity documented in the [developer guide](../../kanz/dev/README.md).

The proof obtains the database role information and credential from its own running risk-engine container. Subprocess credentials travel through child environments. Phase diagnostics report statuses. The parent checks all Docker network identities and rebinds each published loopback endpoint at startup baseline, ordinary shutdown and final cleanup. The direct inputs select the qualification automatically; shared transitive Go changes continue through ordinary kanz-ci and can select the full lifecycle by workflow dispatch. The [Redpanda publisher](https://docs.redpanda.com/streaming/current/deploy/redpanda/kubernetes/k-production-deployment/#failed-to-pull-image) identifies Docker Hub as the origin behind its analytics alias. Acquisition requires the same pinned index and keeps the canonical Compose reference in the guest.
