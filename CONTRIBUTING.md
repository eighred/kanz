# Contributing to Kanz

Read [AGENTS.md](AGENTS.md) for Kanz's architecture, safety and evidence rules,
then [the developer setup](kanz/dev/README.md) for the actual local environment.
The root [README](README.md) explains the product and component entrypoints.

Use the shared [Eighred repository organization standard](.agents/plugins/kanz-forge/skills/repository-organization/references/eighred-standard.md)
when placing code, naming directories, writing component documentation or moving
a component. Developers and Kanz Forge use this single maintained standard.

Retrieve decisions and acceptance from [GitHub Issues](https://github.com/eighred/kanz/issues),
implementation and verification history from PRs and git. Keep transient plans
in the chat. Do not add repository progress logs or a second project-state store.

For engineering workflow and supported Codex setup, use the
[Kanz Forge guide](.agents/plugins/kanz-forge/README.md). A documentation or source
change does not authorize infrastructure operations or live capital activity.
