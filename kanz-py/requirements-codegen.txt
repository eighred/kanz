# BUILDER-STAGE LOCK — the protoc toolchain that emits the Python schema SDK.
#
# Separate from requirements.txt on purpose: this is what GENERATES /app/gen in
# the builder stage, and none of it ships in the runtime image. Merging the two
# would put setuptools and a second protobuf into the deployed layer to satisfy a
# build-time need.
#
# grpcio-tools was already version-pinned in the Dockerfile before this file
# existed — but a version is not an artifact, and its THREE TRANSITIVE
# dependencies were unpinned and unnamed. The protoc that emits every message
# this platform's AI layer reads was therefore partly floating, and a stub
# generated by a different protobuf than the one recorded here is a different
# wire contract. The Dockerfile now installs from this lock and names no version
# of its own.
#
# TO REGENERATE (from the repository root, network required) — same procedure as
# requirements.txt, with the grpcio-tools pin as the only input:
#
#   python -m pip install --dry-run --ignore-installed --report /tmp/b.json #     --target /tmp/discard #     --python-version 3.12 --implementation cp --abi cp312 #     --platform manylinux2014_x86_64 --only-binary=:all: #     "grpcio-tools==1.83.0"
#
# Moving grpcio-tools is a deliberate act: change the specifier above, rerun,
# and REGENERATE THE GO SDK TOO (`cd kanz-schemas && buf generate`) so the two
# language SDKs are not emitted by different protoc versions.
#
# PLATFORM: linux/amd64, CPython 3.12 — see requirements.txt's PLATFORM note.
#
# THE arm64 BLOCKER RECORDED HERE IS RESOLVED. This file used to state that
# grpcio-tools 1.68.1 publishes no manylinux aarch64 wheel, "which is the reason
# an arm64 build of this image is not possible at any pinning level". That
# premise died with the bump: 1.83.0 resolves cleanly for
# manylinux2014_aarch64 with the same five packages. An arm64 image is now a
# question of wanting one, not of availability — the hashes below are still
# amd64-only, so building for arm64 means regenerating this file for that
# platform, not merely changing a --platform flag at build time.
#
# GENERATED 2026-08-10 against pypi.org. Every hash was resolved by pip AND
# independently re-fetched from https://pypi.org/pypi/<name>/<version>/json and
# compared; none is hand-written.
